## 1. 攻击目标

按可达性从高到低，我设定的还原目标依次是：

1. 混淆器的**字符串常量表**（被加密的 API 名、报错文本、魔术串）。
2. 混淆器的**数值常量编码**（所有 `R[i][j](a,b)` 形式的立即数）。
3. **控制流结构**：模块骨架、平坦化调度、opaque predicate。
4. **载荷容器格式**：那个 207KB 长字符串到底是什么、怎么解。
5. **防御/反调试逻辑**。
6. **虚拟机指令语义**：指令格式、寄存器/常量编码、opcode 表、各 handler 行为。
7. （stretch）**字节码解密 + 反汇编**——第三轮完成"解密 + 结构还原"（✅ 字节精确），第四/五轮完成"常量明文"（✅ 705/707 槽）。**只剩"反汇编到 Lua 语义"（反虚拟化）未做**，见 §5.1bis / §5.6。

## 2. 逐步流程（假设 → 操作 → 观察 → 结论）

### 步骤 1：定骨架
- **假设**：单行 404KB 文件不可能靠肉眼读，必须先词法化 + 找到顶层结构。
- **操作**：写了一个 Lua 词法分析器（处理 `0X...` 十六进制、`[=[...]=]` 长字符串、转义），得到 **92,174 个 token**；然后用「花括号深度 + block 栈（`function/if/for/while/do/repeat-until` 分别处理）」扫描 `return({...})` 的顶层键。
- **观察**：第一次扫描（只数花括号）给出 2900 个"键"，明显是把函数体内的赋值误认成表键；改用 block 栈后得到 **32 个顶层键**，且长度分布极不均匀：`kn` 独占 260,475 字符，`ye` 27,818，`yJ` 17,573。
- **结论**：模块返回一张 32 键的方法表。**长度异常即语义异常**——`kn` 是主体，`ye`/`yJ` 是次级大块。

### 步骤 2：找到入口
- **假设**：一个只 `return` 表的 chunk 不是完整程序，一定还有后续调用。
- **操作**：看文件最后 300 字符。
- **观察**：结尾是 `}):yq()`。
- **结论**：返回的表被**立刻用自己的 `yq` 方法调用**，`self` 即模块表自身。于是所有 `R:kr()` / `R:kg()` / `R:bR()` / `R:kn()` 都是**自调用**，`R` 就是这张 32 键表。这一步把"一堆匿名函数"变成了"一张有名字的方法表"，是整个分析的支点。

### 步骤 3：抓住 `bk` —— 常量解码表（第一个突破口）
- **假设**：满屏的 `R[98][0X64](0XAC2BE221,0X00028432C92)` 一定是"用两个大数算出一个真常量"，那么定义这张二维表的地方就是密钥。
- **操作**：定位到那个用 `function` 定义、且内部构造 256×256 查找表的键（`bk`）。
- **观察**：`bk` 先用**半字节异或表**拼出 256×256 字节异或表，再拼出 32 位 `xor32`、`band`、`rshift` 的纯 Lua 实现（说明它要在**没有位运算库的 Lua 5.1** 上跑），最后装配出 **24 个 `OP[i][j]`**，每个只有两种形态：
  - `xor` 型：`return K1 ^ (b ^ a)`
  - `add` 型：`return a + b - K2`
- **结论**：**全部 354 处 `R[i][j](a,b)` 都可静态求值**，无需运行。这是最便宜、收益最大的一步。

### 步骤 4：抓住 `kg` —— 字符串解密小 VM（第二个突破口）
- **假设**：`b({...}, 366)` 这种「字节数组 + 数字种子」的调用是字符串解密；它的实现里应该有一张 256 项置换表和一个逐字节发射循环。
- **操作**：读 `kg`。
- **观察**：`kg` 内部是一个**微型 handler-VM**：`RQ`（19 项 handler-id 数组）+ `Rz`（id → 处理函数的字典）+ 一个 `while true do local h=Rz[RQ[Xd]]; if h then h(state); Xd=Xd+1 else break end end` 调度循环。11 个 handler：`Cw`(init) `Ca`(nop) `Xf`(PRNG 步进) `Xj`(取位置/前字节) `Xy`(混合出 XC) `Xs`(查 SBOX) `Ci`(发射字符) `Xv`(载密文) `Xb`(推进指针) `Cq`(校验和) `XU`(循环/退出)。SBOX 由 `RW(RE)` 用固定 16 字节种子 `RE` 做 Fisher–Yates 洗牌生成。
- **结论**：可完全离线复现。**但第一次复现失败了**（见步骤 5）。

### 步骤 5：用"已知明文"校准，并揪出自己的 bug（最关键的一步）
- **假设**：与其猜，不如找**必然正确**的明文。
- **操作**：在 `bR`（API 解析器）里找结构证据：`Rt = RR[R[0x647D1499]]`，末尾 `Rt(b, {[R[1121133507]] = R[673945751]})`。12 字节 + 6 字节 + 1 字节的组合，唯一合理解释是 `setmetatable(b, {__mode="k"})`。又找到 `Rz[R[0x6E76CAD4]]` 被**无参调用后当作环境**用 → 必是 `getfenv`（7 字节，数组正好 7 项）。同理 `bit32`(5)/`bit`(3)/`band`(4)/`bxor`(4)/`rshift`(6)/`string`(6)/`tostring`(8)/`char`(4)/`find`(4)/`type`(4)。
- **观察 1**：把 15 个锚点一起跑，得到 **11 处 XC→XR 冲突**，而 69 个样本在 256 桶里的随机碰撞期望正好是 69×68/2/256 ≈ 9.2。**11 ≈ 随机期望 ⇒ 我的 XC 轨迹是错的**（如果对了应该是 0 冲突）。
- **观察 2**：关键推理——`Xf`/`Xy` 只用 `Cp/XX/Co/Ch/Xk`，**完全不碰 SBOX**，所以 XC 序列与 SBOX 无关，冲突只能来自初始状态 `(RU,Rd)` 或状态机。而状态机由 `RQ`/`Rz` 逐字确定（我还专门验算了 19 个 handler-id 的十进制/十六进制字面量两两相等）。
- **结论（我的 bug）**：我的 Python 里 Fisher–Yates 洗牌循环用了 `Rd` 作循环临时变量，把**洗牌前**保存的 `Rd` 覆盖成了**洗牌后**的值；而 Lua 源码里那句是 `local Rd=...`，是循环体局部变量，外层 `Rd` 不受影响。改名后 **15/15 锚点全部通过**。
  - 顺带证明：`if (Rf%2)==0 then ... else ... end` 里 `Rf` 是环境指纹，但**两个分支逐字符等价**——它是纯 decoy，不影响 SBOX。

### 步骤 6：批量抽取字符串表
- **操作**：在 token 流上扫 `name ( { num/op... } , num )` 形态（允许括号内的模数变量是 name token），求值数组（`%v`/`%k`/`%Rj` 一律 = 256，因为 `kg` 返回的第三值就是 `0x100`），逐条解密。
- **观察**：**109 处调用，87 个唯一串**，全部为可读 ASCII（少数是刻意的二进制键材料）。
- **结论**：完整 API 表面浮现——`getfenv/setfenv/getgenv/getrenv/loadstring/load/newproxy/raknet/Luau/typeof/debug/getinfo/source/=[C]/what/S/collectgarbage/newproxy/__mode/k/__index/__newindex/'for' limit must be a number/KryvexObf_/kryvex/1%@`。**看到 `getgenv`+`getrenv`+`Luau`+`typeof`+`raknet` 就能判定目标是 Roblox 脚本环境。**

### 步骤 7：抓住那个 207KB 长字符串
- **假设**：`kn` 里 260KB 的体积大部分不是代码而是数据。
- **操作**：定位 `[=[` … `]=]`，长度 **206,879**，位于偏移 99,280–306,162；统计其中所有 `/xxxxx` 5 字符序列。
- **观察**：**恰好 8 种标记**，每种 130–183 次：`/b!k``、`/9Ux0`、`/Snx:`、`/9Y<[`、`/t;Cz`、`/=KzM`、`/hga"`、`/~4Ha`。全文只用 **83 种字符**。
- **结论**：这是带转义标记的 token 流，不是随机数据。

### 步骤 8：在 `ye` 里找到标记映射表（第三个突破口）
- **假设**：8 个标记必然在某处被映射成语义符号。
- **操作**：读 `ye`（27,818 字符）末尾的 `Cu`。
- **观察**：一张明文表 —— 
  ```lua
  {['/hga"']="#", ['/9Ux0']='"', ['/b!k`']="$", ['/=KzM']="}",
   ['/9Y<[']="'", ['/t;Cz']="%", ['/~4Ha']="&", ['/Snx:']="!"}
  ```
  以及一个扫描器：遇 `/` 取 5 字符，命中则替换为符号并跳 5，否则原样输出 `/` 并跳 1。
- **结论**：标记替换 = 把载荷变成可安全嵌入 Lua 长字符串的可打印文本。

### 步骤 9：认出 base-86 数字系统
- **假设**：`ye` 里 `yn` 函数出现的 `86`、`86^2`、`86^3`、`86^4`、`2^24` 组合是变长整数解码。
- **操作**：读 `yn` + `CU`（构造数字表）。
- **观察**：`yn` 每次读 5 个"数字"→ `v = d0·86⁴+d1·86³+d2·86²+d3·86+d4` → 拆成 4 个大端字节压入缓冲 `CX`，后续调用逐个 `table.remove` 弹出并过 `RW()` 解密。`CU` 用 9 段（部分经 `string.reverse`）二进制串拼出 **91 字符字母表 C** 和 **91 字符取值串 s**，然后 `CC[byte(C,i)] = byte(s,i)-1`。
- **决定性观察**：字母表 **91 = 83（blob 字符）+ 8（标记符号）**，取值恰为 **0..85 各一次**，另有 **5 个字符取值 254**（`*` `/` `G` `T` `i`）是哨兵；blob 里出现但不在字母表的字符只有 `[`(91) 和 `~`(126)——**而它们只出现在 `/9Y<[` 和 `/~4Ha` 内部，替换后必然消失**。三个独立事实互相咬合。
- **结论**：格式完全确定。4 字节密钥 `CM` = `reverse(4段解密串)` 拼接 = `[49,227,162,242,182,80,149,6,122,74,201,72,169,139,1,96]`（16 字节），喂给与 `kg` 同构但**常量不同**的 Fisher–Yates 密钥调度 `RU(CM)`。

### 步骤 10：解开 LZ77 —— `CL`/`CO`/`Cx` 状态机（第四个突破口）
- **假设**：`Cx` 那一坨几百行嵌套 `if` 是平坦化壳，真正语义在它调用的 `R.CE[...]` 闭包里，而那些闭包由 `CO` 定义、由 `CL` 建的 `CW` 表索引。
- **操作**：提取 `CL` 里全部 10 条 `v.CW[...]={...}`、`CO` 里全部 13 条 `R.CE[R.CQ+(id)*R.Cz]=...`，以及 `Cx` 里的取指语句 `CJ,R.Ct = R.CW[R.Ct], R.Ct+1`。
- **观察**：`RR` 是一张 10 项置换（`RR[1]=2, RR[2]=5, RR[3]=7, RR[4]=1, RR[5]=8, RR[6]=10, RR[7]=3, RR[8]=6, RR[9]=9, RR[10]=4`），`CW` 经它间接索引；初态 `Ct = RR[1] = 2`。10 个 handler 的语义分别是：
  | 状态 | 行为 |
  |---|---|
  | 2 | `Ck=8; CG={}` → 5 |
  | 5 | `Ct = (Ck>7) ? 7 : 1` |
  | 7 | `CP = yn()`（读控制字节）; `Ck=0` → 1 |
  | 1 | `Ct = (CP&1) ? 8 : 10` |
  | 8 | **字面量**：`CH=yn(); CG[#+1]=char(CH)` → 4 |
  | 10 | `CB=yn()` → 3 |
  | 3 | `CY=yn()` → 6 |
  | 6 | `CK=yn()` → 9 |
  | 9 | **回溯拷贝**：`Cc=#CG-(CB*256+CY)+1`；复制 `CK+3` 字节 → 4 |
  | 4 | `CP >>= 1; Ck += 1` → 5 |
- **结论**：这是标准 **LZ77 式压缩**（控制字节 LSB 优先，1=字面量，0=匹配：16 位回退偏移 + 长度 CK+3）。跑通后 **1,466 原始字节 → 2,985 字节**，开头正是 `[=[--[[` 加一大片 ASCII 艺术，结尾是真实 Lua 源码。**这是全案最强的正确性证明**——LZ 回溯引用若偏移/长度错一位就会立刻崩，而它一次跑通且产出合法 Lua。

### 步骤 11：还原 Stage 1 装载器
- **观察**：Stage 1 = `[=[--[[<ASCII banner>]]]=] .. string.format(' return setfenv(function(...) return %s(...) end, setmetatable({ ["%s"] = ... }, { ["__" .. "index"] = getfenv and getfenv((...)) or _ENV or _G })) ', 'AwPSEVPFqD', 'AwPSEVPFqD')`。
- **结论**：banner 藏在 `--[[ ]]` 注释里；`loadstring("return "..Rj)()` 求值得到 chunk 源码 `Rf`；`loadstring(Rf,"kryvex")` 得到 chunk；用 continuation `Rs` 调用它 → `Rs()` 解出 **Stage 2**。`AwPSEVPFqD` 是本次编译随机生成的绑定名；`"__".."index"` 是字符串拼接反检测。

### 步骤 12：确认 Stage 2 是字节码而非源码
- **操作**：看 `kn` 怎么消费 `yc` 的返回值 `vh`。
- **观察**：`local function vf() local RR=Rq(vh,Rm,Rm); Rm=Rm+Rv[0x26][0x32](0x22F953DC,0x2314ECAE); return RR end`，其中 `Rq=string.byte`，那个常量 = `0x22F953DC^0x2314ECAE^0x1EDBF73 = 1`。随后 `Rc,RF,Ru,Rx = vf(),vf(),vf(),vf()`。
- **结论**：`vf()` = 顺序读字节；**前 4 字节被当密钥吃掉**；Stage 2 是 119,409 字节二进制字节码（字节分布均匀，256 个值全覆盖，符合加密后特征）。

### 步骤 13：还原字节码读取器 `RS()` 与 `vu()` 原型树
- **观察**：`RS()` 是单字节读取器：4 步解密链 `RR[41]→RR[48]→RR[82]→RR[22]`，再 xor 上一个由位置 `vU` 和全局量 `va` 驱动的三轮 PRNG 输出 `RA`，然后用 4 个更新函数滚动密钥 `Rc/RF/Ru/Rx`。`vu()` 递归解析函数原型：`kE/kz/kP`（三个 32 位密钥字，由 `Rw()` 读 u32 后与 `RV` 及 `kE` 的循环移位异或得到）、`yE/yt/yl/yQ`（4 个字节）、`yP`（子原型数组，用**保存/恢复游标与密钥状态的 thunk 惰性加载**）。
- **结论**：这是 **Luraph 式**设计——每个函数原型自带密钥调度（`kd` 填 `kM/kL/kW/kO` 四条平行数组），常量按原型逐个解密。

### 步骤 14：修正一个隐蔽误判——`kA` 的第一个函数不是加法
- **假设**：`kA` 返回 `(add, shr)`。
- **操作**：手算 `RR(5,3)`：核心是 `Rb=((R%2)+(v%2))%2; RR=RR+Rb*Rv`，**没有进位传播**。
- **观察**：得到 6，而 5+3=8，5^3=6。
- **结论**：它是 **XOR**，不是 ADD。第二个函数 `(R*(256/2^v))%256 + (R-R%2^v)/2^v` = `(x mod 2^v)·2^(8-v) + (x>>v)` = **8 位循环右移 rotr8**，不是逻辑右移。这两个误判会直接毁掉整条密钥流。

### 步骤 15：静态复现 `va`（走到这里卡住）
- **操作**：`kF` → `RZ`（纯常量链，含 `string.byte(tostring(math.floor(0x60EB8AC9F93)),9)` 等）；`yJ(math.floor)` → 256×256 字节异或表、`xor32`、`rotl32`；`kI` → 8 项密钥表 `Rb`、PRF `Rf`、`va`。
- **观察（强正反馈）**：`kI` 里 8 个键 `Rs[1..8]` 经 `bk` 解码后**正好落在整数 1..8**，而两处查表用的键 `key1=2`、`key2=7` **都命中**——这不可能是巧合，反证我的 `bk` 常量解码与 `kI` 重建完全正确。算得 `RZ = 0xE5BA68B9`、`va = 722570424`、密钥态 `(Rc,RF,Ru,Rx) = (961656861, 9, 14728, 243)`。
- **观察（卡点）**：用它们跑 `RS()` 得到的高熵字节流**无法自证对错**——它本来就该是高熵的（前几十字节是 `kE/kz/kP` 密钥材料）。而 `va` 只要差 1，整条密钥流就全变。
- **结论**：算法与常量 100% 还原，但缺一个可判定的 oracle，见第 5 节。

- **观察/结论**：见第 4 节"VM 指令语义"。

## 2bis. 第二轮攻坚（续：步骤 17–26）

第一轮结束后我在报告里写了三条**错误**结论（"RZ 依赖宿主 Lua 数字格式化"、"不存在 oracle"、"搜索空间 2^31"）。第二轮先把它们推翻，再建立了完整的判定体系。

### 步骤 17：找到硬 oracle —— `kd()` 的循环上界 `kQ`
- **假设**：字节码里一定存在某个"必须在很小范围内"的量，可以当判据。
- **操作**：dump `kd` 全文。发现 `local RU=R(s(),R(k(v.kE,0XB),k(C,0X7)))` → `v.kQ=RU`，随后 `while Rb<RU do ... end`，每轮消耗 `s()`(4B) + `X()`×3(12B) + `Rz=((s()>>29)%4)` 个额外字节 = **16–19 B/轮**。
- **观察**：`kH` 里有 `local Rv=v.kP; local Rz=Ry+v.kQ; while Rv<Rz do Rv=Rv+1; local RP=v.kM[Rv] ...`——它把 `kP` 当基址、`kQ` 当条数遍历 `kd` 刚写入的 `kM/kL/kW/kO`。**两处独立互证：`kQ` 就是这个原型的指令条数。**
- **结论**：预算 119405 B ÷ 16 B ⇒ **`kQ ≤ 7461` 是硬约束**。超过就会 `string.byte` 越界返回 nil → 算术报错。**这就是我要的 oracle，且它比 `nChild` 早得多、不需要先实现 `yo()`。** 第一轮"不存在 oracle"的说法作废。

### 步骤 18：证明 `RZ` 是纯常量，与宿主 Lua 无关
- **假设**：第一轮认为 `kF` 的常量链依赖数字格式化。
- **操作**：逐项定位环境表条目。`R[0X2267BA0C]` 是唯一环境相关项（`type(0xB948*1)==R[0X2267BA0C]`）。用已破解的 `kg` 解码器把 `bR` 里全部 58 个字符串字面量解出来，得到 `b[0X2267BA0C] = R[0X24D80404] = "number"`。
- **观察**：于是 `t5 = 0x1D88 = 7560`。其余六项：`tostring(math.floor(0x60EB8AC9F93))` = `"6660297629587"`（13 位，`%.14g` / `%d` 在 Lua 5.1/5.2/5.3/5.4/LuaJIT/Luau 下**输出完全相同**）⇒ `t1=50`；`#tostring(math.floor(0x33669CD7BAC))` = `#"3532238191532"` ⇒ `t3=13`；`floor(sqrt(0x536C3806B9))%256 = 598579%256` ⇒ `t4=51`；`0x1B142453%0xA7FF` ⇒ `t2=21910`；`string.byte("`wqrB",2)` ⇒ `t6=119`；`floor(0x5E8478790C6/7)%37661`（商的整数部分 927884374044，小数部分 0.2857，距 0 和 1 都远大于该量级的 ulp≈1.2e-4，IEEE754 正确舍入下**不可能**差 1）⇒ `t7=37600`。
- **结论**：**`RZ = 0xE5BA68B9 = 3854198969` 是完全确定的，不存在任何跨版本歧义。** 第一轮"混淆器把密钥绑定到宿主数字格式化"的推测**是错的，正式撤回**。

### 步骤 19：三重交叉验证 `bk` 常量表
- **操作**：把 `vu()` 里 `RI[...]` / `RN[...]` 两个 handler 表的键用 `bk` 解出来。
- **观察**：`RI` 的键 = **{4, 26, 56, 44, 228}**，而 `RI` 是用 `local Rb=RI[(Ry)]`（`Ry=RS()` 一个字节）索引的 ⇒ 键**必须**落在 0..255，全部命中。更妙的是 `RN` 的键 = **{4, 26, 56}**（外加一个 decoy 218），而 `RN` 是用 `RN[(Rv[(1)])]` 索引的，`Rv[1]` 来自 `RA[Rv]={0X04,...}` / `{0X01A,...}` / `{56,...}` —— **三个常量类型码与三个 handler 键一一对应**。另外 `yc` 里的 `s[0X7B][0X63](924433702,874119316)` = **1**（正是 `string.sub(blob,1)` 的偏移），`yS` 里的空串哨兵 = **0**。
- **结论**：`bk` 的 24 个 `(槽位,运算,密钥)` 被**四条相互独立的结构性证据**锁死，不可能是错的。

### 步骤 20：完整静态恢复运行时环境表 `Ry`
- **操作**：解析 `bR(self, b=Ry, R=RP, k=RB, v=256, y=vM)`，把其中 58 个 `R[<hash>]=k({...},key)` 用 `kg` 解码器全部解出，再把 46 条 `b[<hash>]=...` 右值映射到 `_ENV[名字]` / `math[名字]` / `string[名字]` / `table[名字]` / 字面串。
- **观察**：得到完整的 hash→语义 映射（见 `analysis/env_recovered.txt`）。关键项：`0x49E8C28B=string.byte`、`0x638C2532=math.floor`、`0x6A980CC6=tostring`、`0x3C4BF2E3=string.sub`、`0x3DEFC115=table.concat`、`0x685B2FE4=string.char`、`0x6E32F2E5=unpack`、`0x3192D86E=table.remove`、`0x755084B8=string.reverse`、`0x80139E0=table.insert`、`0x2267BA0C="number"`、`0x64EE8564="Luau"`、`0x6A17615F="1%@"`、`0x39184D20="what"`、`0x1521DF2E=debug`、`0x6057E1FF=setfenv`、`0x3187F30C=newproxy`、`0x4EDB0E60=typeof`、`0x5F8FF999=getgenv`、`0x0B618D5B=raknet`。
- **结论**：这一步把 `kI` 的第 6 个实参 `vy` 钉死为 **`math.floor`**（而不是我一度怀疑的 `tostring`）。判据是行为矛盾：`kI` 里 `X(Ry/2^32)`、`X(Ry/0x10000)`、`X(Ry/0x1000000)` 的结果要喂给 `xor32`，若是 `tostring` 会产生小数下标使 `Rv[小数]` 取到 nil 而崩溃；而 `math.floor` 恰好解释了为什么返回的 `RF` 就等于种子第 2 字节 **9** 不变（因为 `floor(Ry/2^32)=0`）。

### 步骤 21：**关键突破——`:` 方法调用约定**
- **假设**：`yc`/`ye`/`Cu`/`kF`/`bk`/`kI`/`kd`/`yS`/`yJ` 的形参绑定一直对不上（例如 `yc` 里出现 `s[0x7B][0x63](...)` 却要求 `s` 是取字节函数；`ye` 里 `Cf=#X` 却要求 `X` 是字符串而调用处传的是 `0X9C5`）。
- **操作**：注意到 `kF`/`bk`/`kA`/`yJ`/`kd` 的形参表都以 `_` 开头且带**重复的 `_`**（如 `function(_,R,_)`），而调用一律是 `R:kF(Ry)` 这种冒号形式。
- **观察**：**冒号调用会把 self 绑到第 1 个形参**。把这一层补上后，所有矛盾**同时消失**：`ye=function(_,y,b,R,k,v)` ← `(self, blob, env, RP, RB, 256)`；`Cu` 是 `T:Cu(...)` 所以 `C=self`（方法表，故 `C:Cx(s)` 合法）、`X=blob`（故 `Cf=#X` 合法）、`_=0X9C5`、`s=string.byte`（故 `s(b,R)` 合法）、`y=string.sub`（故 `y(X,1,0X9C5)` 合法）、`f=RL`（loader，故 `f(src)` / `f(chunk,name)` 合法）；`yc` 里 `s=Rv`=bk 运算表（故 `s[0x7B][0x63]` 合法）、`f=kX=string.sub`、`C=blob`；`kd` 的 11 形参 ← `(self, RR, vt, Ry, Rv, RX, Rd, Rw, kj, RS, RV)`，即 **`R=xor32, k=rotl32, s=Rw(4字节读), X=kj(带符号读), f=RS(1字节读), C=RV`**。
- **结论**：这是本轮最大的方法论收获。**第一轮我少算了一层 self，导致对多个函数的实参语义判断错误。** 修正后 `kd` 里 `s()`=`Rw()` 而非 `RS()`，`X()`=`kj()`，全部对齐。

### 步骤 22：证明 `vh` 就是那 119409 字节
- **操作**：顺着 `yc → ye → RR(y) → T:Cu(...) → (function(s) ... end)(state)` 一路读完，并把 Stage 1 源码的返回值代进去。
- **观察**：`RC=f(prefix..Rj)` 载入 Stage 1；`Rf=RC()` 运行它，得到字符串
  `return setfenv(function(...) return AwPSEVPFqD(...) end, setmetatable({["AwPSEVPFqD"]=...},{["__".."index"]=getfenv((...)) or _ENV or _G}))`；
  `RX=f(Rf,name)` 再载入它；`Rd=RX(Rs)` 以 part-2 解码闭包 `Rs` 为 `...` 调用 ⇒ 得到转发闭包 `G`，其环境里 `AwPSEVPFqD` 就是 `Rs`；`return Rd()` = `G()` = **`Rs()`** = `C:Cx(s)`（part 2）。而 `Cx` 的返回是 `unpack(CI,1,Cr)`，`CI={table.concat(CG)}`，`CG` 只由字面量 handler `CG[#CG+1]=string.char(yn())` 填充。
- **结论**：**`vf() = string.byte(vh,Rm,Rm)` 读的正是我的 `stage2_bytecode.bin`**，`Rm` 从 1 开始、前 4 字节作密钥、第 5 字节起进 `RS()`。第一轮的 `yc`/`kk` 疑虑排除。

### 步骤 23：把 LZ77 状态机逐状态重建，证明 part 2 是纯字面量流
- **操作**：dump `CL`/`CO` 全文。发现其中反复出现的 `Rv(a,b)` 其实是 `ye` 里的 `local Rv=function(R,v) local Rv=(R+#RR)%2 return v+Rv-(R%2) end`，而 `#RR==10` 是偶数 ⇒ `(R+10)%2 == R%2` ⇒ **`Rv(R,v) ≡ v`，是恒等函数**。
- **观察**：于是所有 `Ct=Rv(0X1CE2,RR[1])` 之类的表达式**都塌缩成 `RR[1]`**，`CW` 也不是"稀疏到 28861 的怪表"，而是干净的 10 项：`CW[1..10] = {428,146,760,1037,296,809,310,546,961,678}`；配合 `CE[CQ+(code+CS)*Cz]` 得到完整转移：
  `2:(Ck=8,CG={},→5)  5:(Ck>7?→7:→1)  7:(CP=yn(),Ck=0,→1)  1:(CP奇?→8:→10)  8:(CH=yn(),CG+=char(CH),→4)  4:(CP>>=1,Ck+=1,→5)  10:(CB=yn(),→3)  3:(CY=yn(),→6)  6:(CK=yn(),→9)  9:(回溯复制 CK+3 字节,→4)`，初值 `Ct=2`。
  又 `yn` 首行 `if C.Cv and C.Ck>7 then return 0XFF end` 在 `#X>0` 缓冲检查**之前**，而每 4 个字面量恰好耗尽一个 5-token 组的缓冲、每 8 个字面量恰好把 `Ck` 推到 8 ⇒ **控制字节永远走 0xFF 免消耗路径，缓冲区永远不会被跳过**。
- **结论**：`Cv=true` 时 part 2 **可证明**是纯字面量流，1 token 组 → 4 字节（尾组 2 token → 1 字节），`149262 = 5×29852+2` ⇒ **119409 字节**，且 `119409 = 8×14926+1` 正好在末尾触发 `R>C.Cf → nil → CA=true` 正常终止。**B2 逐字节确认。** 我还重新执行了 `run.py`，产出的 sha256 与已交付的 `stage2_bytecode.bin` 完全一致；`lz.py` 重跑 part1 也精确消耗 1466 字节并输出与 `stage1_recovered.lua` 逐字节相同的 2985 字节。

### 步骤 24：`vu()` 状态机顺序与"无旁路消耗"证明
- **操作**：把 6 个 `elseif Rb==<常量>` 的十进制/十六进制对上，并在 `kn` 全文 grep `RS()` / `Rw()` / `ks()` / `kj()` / `vf()`。
- **观察**：状态序为 **3358 → 6806(0x1A96) → 12057 → 15450(0x3C5A) → 19613(0x4C9D) → 23216(0x5AB0, 退出)**。`RS()` 全部 8 处、`Rw()` 全部 7 处、`ks()` 唯一 1 处**都在 `vu()` 内部**；`vf()` 全部 6 处 = 1 处定义 + 4 处种子读 + 1 处在 `RS()` 内；`kj()` 在 `kn` 里 **0 次**（只经参数进 `kd`）。`ku/yu/ki/kG/yD` 的实参是 `...,Rq,vy,vC,vb,Ra,Ri,Rn,RW,RM,RO`（string.byte/floor/char/concat），**既没有 `RS`/`Rw` 也没有 `vh`**；`yo` 与 `kH` 同样不读流（`yo` 返回的是两张表 + 两个代理 + 类型篡改函数 + 名字哈希函数 + 3 个常量，即反篡改/名字混淆子系统）。
- **结论**：`vu()` 之前**没有任何东西消耗字节流**，`Rm` 在进入 `vu()` 时确定为 5。另外 `kd` 的返回值会**覆写 `RV`**（`RV=R:kd(...)`），状态 12057 末尾再覆写一次，所以 `Rh` 用的是 RV₂、`nChild` 用的是 RV₃——这一点第一轮完全漏掉了。

### 步骤 25：定位并修掉自己两个真实 bug
- **操作**：把第一轮的 `oracle.py` 与本轮从零重写的 `crack.py` 逐项对拍。
- **观察**：两者算出的 `va`/`RV`/`kE` 全不相同。根因是 `oracle.py` 的两个 bug：
  1. 把源码里的 9 位十六进制字面量 **`0X14ED16EC9`（=5617512649）截写成了 `0x1ED16EC9`**，直接毁掉 `RXa[3]` ⇒ `Rb` 表的第 4 个值全错 ⇒ `RV` 全错。
  2. 在 `RR[0x60]`（更新 `RF`）里多加了一个 `&0xFF`，而源码是 `RX(R,Rc)` 不做截断——只有第一次调用时 `Rc>255` 会有差别，但那一次就足以带偏整条状态链。
- **结论**：`crack.py` 是逐字忠实版本，其 baseline（`va=961330124, RV=0x69C17017, kE=0x579359E4, kQ=3574921221, yt=11, yQ=224`）与 C 实现逐位一致。**第一轮报告里写的 `va=722570424`、`(961656861,9,14728,243)` 作废。**

### 步骤 26：六次穷举/结构搜索（全部为负）
- **假设**：既然每一环都被逐字验证，那故障必然落在某个仍可自由变化的参数上。
- **操作**（均用 C，`-O3 -march=native`）：
  1. **`Ry` 全空间 2^32**（`Ry` 是 `kI` 的中间量；`(Rc,RF,Ru,Rx)` 与 `va` 都是它的函数，而 `RV` 与它无关，因此这一维覆盖了"状态错"和"va 错"两种情形）：判据 `yt≤8 ∧ yQ≤64 ∧ 0<kQ<7462` → **80 个命中，用完整递归解析验证器逐个否掉（0/80）**。命中数与随机期望 66 吻合。
  2. **`RV` 全空间 2^32**（关键结构事实：`RV` **完全不进入 `RS()` 密钥流**，所以整条 119405 字节密钥流可以预先算一次，`RV` 变成纯自由变量）：`kQ<7462` 的一级筛出 **7472 个**（与理论值 7462 吻合），二级用完整解析 → **0 幸存**。
  3. **`va` 全空间 2^31**（状态固定）：**190 个命中，0/190 幸存**（随机期望 193）。
  4. **5184 个结构变体**（流起始偏移 ×9、`vU` 偏移 ×3、rotl/rotr ×2、`RR[82]` 异或源 ×4、`RR[48]` 方向 ×2、`Rw()` 打包 ×3、`RA` 符号 ×2、是否用原始种子 ×2）：**无一同时满足三个判据**。
  5. **`RZ` 联合扫描 2^32**（进行中）：这是唯一能让 `Ry` 与 `RV` **沿真实曲线一起变化**的搜索，因为二者都是 `RZ` 的函数。

### 步骤 27：先推翻"存在未知密钥"这个前提（方法论上的转折点）

- **假设**：前六轮（含六次穷举搜索）都默认"内层密码存在某个未知密钥，需要搜索"。
- **操作**：把 `vf()` 初始化 → `kI` → `RV1` → `vu()` 的每一个输入逐个列出，对每一个都问一句"这个值从哪来、能不能静态算出"。
- **观察**：
  | 输入 | 来源 | 是否静态可知 |
  |---|---|---|
  | `vh` | `R:yc(...)` → `ye` → LZ77 part 2 | **已证**（sha256 复现） |
  | `Rm` 初值 | `Rv[0x26][0x32](0x22F953DC,0x2314ECAE)` = `a^b^0x1EDBF73` = **1** | 是 |
  | `Rc,RF,Ru,Rx` 初值 | `vf()`×4 = `vh[1..4]` = `146,9,217,202` | 是 |
  | `RZ` | `kF` 第二返回值，7 项全是常量 | **已证** = `0xE5BA68B9` |
  | `vX` | `kF` 第一返回值，依赖宿主 `tostring(function)` | **无关** ↓ |
  | `Rp`(8 值表) / `Rf`(PRF) / `va` | `kI` 内部，全部由 `bk` 常量 + `RZ` + 上面 4 个字节算出 | 是 |

  | `RX`,`Rk` | `R:kA()` = (异或, 8 位循环右移) | 是 |
  | `Rw`,`kj`,`ks` | `R:yS(...)`，纯 LE-u32 / 有符号 / 长度+串 | 是 |

  `vX` 为什么无关：`kI` 里 `f` 只出现在 `if(f%0X2)==0 then ... else ... end`，而两个分支分别是

### 步骤 28：`yc` 没有 self 占位形参（修正第 21 步的过度概括）

- **假设**：第 21 步确立的"`:` 调用把 self 绑到第一个形参"意味着"每个方法第一个形参都叫 `_`"。

  `R:yc(Rk,Ry,RP,RB,Rj,Rt,Rv,Rq,kX)`（9 个实参）的真实绑定是：
  `y = R`(对象本身)、`C = Rk`(那个 206879 字符的 blob)、`v = Ry`(环境表)、`R = RP`、`b = RB`、`k = Rj`、
  `X = Rt`、`s = Rv`(bk 表)、`j = Rq`(string.byte)、**`f = kX`(string.sub)**。
- **结论**：`yc` 的返回式 `return Rb(f(C, s[0x7B][0x63](924433702,874119316))), ...` 里
  `s[0x7B][0x63](...)` = `924433702+874119316-0x6B33BDB9` = **1**，所以 `f(C,1)` = `string.sub(blob,1)` = 整个 blob；
  `Rb(C) = y:ye(C,v,R,b,k)` = `对象:ye(blob, 环境表, RP, RB, Rj)`。整条链自洽。
  **反证**：若按"`y`=blob、`f`=nil"读，`f(C,1)` 就是"调用 nil"，脚本根本无法运行 —— 说明旧读法必错。

### 步骤 29：**根因 —— `kI` 里 `Rv` 被遮蔽成 `0x100`**

- **假设**：`kI` 末尾那段 rekey 是 32 位的（`oracle.py` 与 `crack.py` 两版都这么写）。
- **操作**：逐字读 `kI` 的**头部一行**和 rekey 的四行。
- **观察**：头部是

  ```lua
  nd,kI=function(_,R,f,s,v,j,X,k,b,y,C)local RR,Rv,Rk=0X100000000,0X100,0X6A;
  ```

  也就是在 `kI` 的函数体作用域里 **`Rv` = 256**（`RR`=2^32，`Rk`=0x6A 只用于 `R[Rk][0X1B]` 这类索引）。
  而 rekey 是：

  ```lua
  k=v(k,Ry%Rv)          b=v(b,X(Ry/Rv)%Rv)
  y=v(y,X(Ry/0X10000)%Rv)   C=v(C,X(Ry/0X1000000)%Rv)
  ```

  代入 `Rv=256` ⇒ 取的是 `Ry` 的**四个字节** `Ry%256`、`Ry/256%256`、`Ry/2^16%256`、`Ry/2^24%256`，
  而**不是** `Ry%2^32`、`Ry/2^32`、`Ry/2^16`、`Ry/2^24`。
  （注意 `Rf` 内部有自己的 `local Rv,Rk=0X100000000,0X10000`，只在 `Rf` 体内生效，不影响这四行。）
- **结论**：`Rc/RF/Ru/Rx` 经过 `kI` 之后**仍然是 [0,256) 的字节** —— 这正是 `RS()` 的
  `rotr8` 与所有 `%0X100` 所要求的值域。之前两版把 `Rc` 变成了 u32（如 1961775597），
  `RR[44]` 的 `Rc=RX(rotr8((Rc+R+Rx+(vU%256))%256,5),v)` 虽然 `%256` 兜住了不崩，
  但 `RR[22]` 的 `(Rc+RF+(vU%256)*0xC3)%256` 与 `RR[12]`/`RR[40]` 的状态链从此全部错位，`RS()` 输出全错。
- **修正后的实际数值**：
  `Ry0 = 961656975 = 0x3951B88F`，四字节 `[143,184,81,57]`；
  `Rc,RF,Ru,Rx = 146^143, 9^184, 217^81, 202^57 = (29,177,136,243)`（全部 <256 ✓）；
  `va = 1846030990`；`RV1 = 0x4341F089`。
- **立即结果**：`kE=0x93861D03  kz=0x015B665F  kP=61  yE=0  yt=0  yl=2  yQ=27`，

### 步骤 30：第二个 bug —— `kI` 的 `Rb` 表用了裸异或，而不是 `bk` 的异或槽

### 步骤 32：`RV3` 被运行校验和污染 —— 用"反解 `nChild`"精确绕过

- **观察**：12057 结束时

  > **`RV3 = rotr32(RW4 ^ nChild ^ rotl(kE,15), 5)` 是 `nChild` 的双射。**

  又因为**只有真 `RV3` 才能让孩子原型的头部合法**，枚举 `nChild` 就等价于**精确求解** `RV3` —— 不是启发式。

### 步骤 35：读出 `yD` 的全貌 —— 它不是一个函数，是一整套分组密码

`yD` 长 10394 字节（偏移 391428..401822）。方法体作用域常量：
`Rk=0x2A78B299  Ry=2^32  RC=0x100  Rf=0x10000  RX=0x62  Rs=0x75  RU=0x10  Rd=0x6A  RM=0x79  RR=2^32`。
实参绑定（`R:yD(Rv,Ry,RT,Rp,RZ,Ro,Rd,RX,vz,vP,vX,Rq,vy,vC,vb,Ra,Ri,Rn,RW,RM,RO)`，22 形参）：
`R`=bk 表 `s`=环境表 `b`=`RT`(kI 的 PRF) `y`=`Rp` `C`=`RZ` `X`=`Ro`(xor32) `j`=`Rd`(rotl32)
`v`=`RX`(xor) **`f`=`vz`（yJ 的 256×256 异或查找表 ⇒ `f[a][b] == a xor b`）** **`Q`=`vP`（`yF` 的返回值）**
`z`=`vX` `d`=string.byte `k`=math.floor `U`=string.char `M`=table.concat `L`=`Rn` `W/O/E`=三个篡改标志（干净路径下恒为 `false`）。

内部依次是：8 项表 `Rv` → `RW`/`Rb`/`RO` 三个 PRF 值 → 16 项表 `RN` → 16 项散布表 `RL` →
密钥扩展 `RE` → 8 字节异或 `RQ` → 64 字节分块流密码 `Rz` → 256 项 S 盒 `Rj` + 置换 `RP` →
四个轮键 `Rt/RH/RA/RI` → 四个解码器 `RG`/`Rr`（数值）与 `RK`/`RB`（字符串）→ 两个派发器 `RV`/`RY`。

### 步骤 36：`Q` 就是 `yF` 返回的那个函数 —— **两段 ChaCha 式 quarter-round**

`Q` 不是 `yD` 内部的，而是形参 `Q` = `vP` = `R:yF(vX,Ro,Rd,Ra,Ri,Rn)` 的返回值。`yF` 里：

```lua
local function Rk(R,v,k,b,C)
  local Rk=((R[v]+y)%0X2)                       -- y = vX
  for Rb=1,0X2 do
    if((Rk+Rb)%0X2)~=Rk then RR(R,v,k,b,C) else Rv(R,v,k,b,C) end
  end
end
```

`Rb=1` 时 `(Rk+1)%2 ~= Rk` **恒真** ⇒ 调 `RR`；`Rb=2` 时 `(Rk+2)%2 == Rk` ⇒ 调 `Rv`。
**所以那个依赖 `vX` 的分支是 decoy，执行序列恒为 `RR` 后 `Rv`。** 展开：

```
RR(st,i1,i2,i3,i4):                     Rv(st,i1,i2,i3,i4):
  st[i1] += st[i2]                        st[i1] += 0xE8076313
  st[i4] ^= st[i1];  st[i4] = rotl(,16)   st[i1] += st[i2]
  st[i3] += st[i4]                        st[i4] ^= st[i1];  st[i4] = rotl(,8)
  st[i2] ^= st[i3];  st[i2] = rotl(,12)   st[i3] += st[i4]
  st[i1] += 0x17F89CED                    st[i2] ^= st[i3];  st[i2] = rotl(,7)
```

旋转量 **16/12/8/7** 正是 Salsa20/ChaCha 的四个旋转常数；轮索引表
`{{2,16,1,6},{4,8,14,13},{11,12,3,15},{10,9,7,5},{4,16,7,15},{2,9,3,13},{10,12,14,6},{11,8,1,5}}`
是 ChaCha 的 8 个 quarter-round（列轮 + 对角轮）把每元组内 4 个下标**打乱**后的版本。跑 **5 轮 × 8 = 40 次**。

### 步骤 37：`RE` 的两个分支**代数恒等** ⇒ `vX` 彻底无关（最后一个"运行时依赖"是假的）

`RE(y,v,C,b)` 用 `if((b+v+z)%Rj)==0`（`Rj=2`，`z=vX`）二选一。我一度以为这就是那个
"依赖 `collectgarbage("count")`、静态不可知"的 1 bit。实际算一下：

- 分支 A：16 个字里 12 个是常量，位置 5/6/13/15 放 `y,b,C,v`。
- 分支 B：`Ry[i]=(RN[i]+0xD5874D67)%2^32`，再在 4 个位置覆写 `b,y,v,C`。
- 而 `RN[i]` 的定义就是 `(分支A的同一常量 + Rk) % 2^32`，且 **`Rk = 0x2A78B299`**：

  > **`0x2A78B299 + 0xD5874D67 = 0x100000000 = 2^32 ≡ 0 (mod 2^32)`**

  ⇒ 分支 B 的 12 个常量项与分支 A **逐字相同**；4 个覆写位置解出来正好是 `{b:6, y:5, v:15, C:13}`，
  也与分支 A 一致。**两个分支输出完全相同。**
- 实测验证：`RE(111,222,333,444)` 与 `RE(111,222,333,445)` 在 `z2=0/1` 下四种组合结果全等。

**结论**：`vX` 在整个 Stage 2 里**没有任何影响**（`kI` 的奇偶分支恒等 + `yF` 的 `Rk` 分支恒等 + `RE` 的分支恒等）。
混淆器在三个不同层次放了三个"看起来依赖宿主运行时"的分支，**三个都是 decoy**。
这与第一轮我撤回的结论 (a) 同源——`kF` 的 `vX` 确实是宿主相关的，但它**被刻意接到了一个不影响结果的地方**。

### 步骤 38：`Rz`/`RQ` = 纯异或流 ⇒ **两层掩码互相抵消**（又一处 decoy）

`RK`/`RB` 各有一层"每 64 字节块前 8 字节不异或、其余异或 `(K+i*step)%256`"的掩码，
中间夹一个 `Rz`；`RG`/`Rr` 同样，中间夹一个 `RQ`。而：

```lua
Rz(b,C,X,k,y):  每 64 字节一块 -> key = RE(Rs,Rj,Rf,chain); out[i] = b[i] xor key[i]
                chain = (chain + O(0x35,0x20,0x25D04295,816239511) + 前8字节输出的LE累加) % 2^32
RQ(y,C,X,k,b):  key = RE(...); return y[1..8] xor key[1..8]
```

**两者都是纯异或**。而前后两层掩码用的是**同一个 `K`、同一个 `step`、同一个长度**
（`#R == #Rk`，因为 `Rz` 不改长度），所以 `raw ⊕ mask` 经过异或流之后再 `⊕ mask` **恰好还原成 `raw ⊕ keystream`**。
`RG`/`Rr` 更直白，源码里就是先 `v(y[i],(RU+i*0x3D)%Rv)` 再 `v(Ry[i],(RU+i*0x3D)%Rv)` 显式撤销。

**推论**：`RK` 与 `RB` 的差别**只剩轮键 `RA` vs `RI`**（`RK` 里那两个不同的常数
`0x6987824E/0x757B/0x25C5/0x552D` 与 `RB` 的 `0xC555984B/0x39E7/0x3FDB/0x369`、
以及步长 `0x67` vs `0x85`，全部因掩码抵消而**无效**）。`RG` vs `Rr` 同理，只差 `Rt` vs `RH`。
这条把要还原的自由参数从 8 个降到 4 个。

### 步骤 39：我读错了一行 —— `RB` 结尾**不是**逆序（96 变体暴力定位）

`RB` 的结尾：

```lua
local RU=#Rk;local RC=""local Rb=RU;while Rb>0 do RC=U(Rk[Rb])..RC Rb=Rb-1;end;return RC
```

我第一遍读成"逆序拼接"。实际 `RC = U(Rk[Rb]) .. RC` 是**前插**，而 `Rb` 从 `#Rk` **递减**到 1，
所以结果是 `char(Rk[1])..char(Rk[2])..…..char(Rk[#Rk])` —— **升序，等于不逆序**。

定位方法（值得记下来）：我发现 **`idx`（= `_Rv-1`）在每个原型内必然是 `0..Rh-1` 的一个排列**
（因为 `RA[slot]` 要给 `Rh` 个常量各占一格）。用根原型跑，前 15 个 `idx` 全在 [1,196] 且互异，
第 16 个突然变成 2452338478 ⇒ 精确定位到"第 15 个常量的 `Rx` 算错了"，而第 15 个恰好是
**全树第一次走 `RB`**（`idx=3` 是奇数）。于是对 `RB` 做 96 个变体（2 组常数 × 2 步长 × 2 轮键 × 2 逆序 × 2 输入逆序 × 2 S 盒步长）
的暴力测试，判据是"能否让第 16 个 `idx` 落回 [0,300]"。**唯一命中：不逆序 + 轮键 `RI`。**
这也顺带独立证明了掩码抵消（4 个命中变体的输出字节完全相同）。

### 步骤 49：`yL` 就是指令解码器，且**四个数组的角色可以用代数唯一确定**（不用搜索）

`RS` 不是直接就是 `kM/kL/kW/kO`，而是由 `kC=R:yL(Rs,Ry)` 返回的闭包**惰性**生成：

```lua
local RS={}
local RF={yH=<初值>, ka=RK, kT=Rx, kh=Rc, yA=R.kP}
local Ri=kC(RS,Rl,Rp,Rs,RF,Ro,Rw,b)
setmetatable(RS,{__index=function(t,pc) while RF.yA<pc and RF.yA<R.kP+R.kQ do Ri() end
                                        return rawget(t,pc) end})
```

`yL` 内层是一个 3 状态机，每调用一次产出一条指令：

```
RO = X[yA]                                   RE = (yH*Ry) mod 2^32
Rt = (RE*Rj + yH) mod 2^32                   Rz = (yH mod Rv)*Rb
RP = (floor(yH/Rv) mod Rv)
Rd = signed( bxor(bxor(j[yA], kh), RE) )     RQ = (bxor(C[yA], kT) - RP) mod 2^32
RM = signed( bxor(bxor(s[yA], ka), Rt) )     RL = (RO - Rz) mod 2^32
yH = (yH*Rf + (RL-b)*RX + RQ*Rs + Rd + RM*RC) mod 2^32
RH = RQ - (RL - b)
if RL mod Rb ~= 0 then swap(Rd, RM)
rawset(RS, yA, {RL, RH, Rd, RM})
```

**四个数组的角色（`X`/`C`/`j`/`s` ← `kM`/`kL`/`kW`/`kO`）不需要试**：`kd` 存的时候用的掩码是

| 存储 | 掩码 | `yL` 里对应的解掩码 | ⇒ |
|---|---|---|---|
| `kM[i]` | `Ry ⊕ kz ⊕ (RRr mod 2^28)` | `X` 被用时**不异或任何键**（`RO=X[yA]` 直接进 `RL`） | `X = kM` |
| `kL[i]` | `… ⊕ (kz ⊕ kP)` | `bxor(C[yA], kT)`，而 `kT = Rx = kP ⊕ kz` | `C = kL` ✅ 恰好剥掉那一层 |
| `kW[i]` | `… ⊕ kP` | `bxor(j[yA], kh)`，而 `kh = Rc = kP` | `j = kW` ✅ |
| `kO[i]` | `… ⊕ kz` | `bxor(s[yA], ka)`，而 `ka = RK = kz` | `s = kO` ✅ |

（其中 `Rq=kP⊕kz`、`RK=kP⊕Rq=kz`、`Rc=Rq⊕kz=kP`、`Rx=Rq=kP⊕kz`，全部由 `Rs`=bxor 化简得到。）
**三处异或键与 `kd` 的三层存储掩码一一对消** —— 这既是角色的证明，也是"`yL` 转录正确"的强自检。

`yL` 头部那 9 个"看起来是大魔数"的常量，用 bxor 一算全是小整数：

```
Ry=65537  RC=17  Rv=256  RX=257  Rs=4097  Rj=17881  Rb=2  Rf=3  b=299886286
```

于是滚动密钥退化成极简形式：`yH = (yH*3 + (f1-b)*257 + RQ*4097 + f3 + f4*17) mod 2^32`，
且所有中间积 < 2^53（最大 `RQ*4097` ≈ 1.76e13）⇒ **double 精确，无浮点分歧**。
`Rb=2` ⇒ **`if f1 % 2 ~= 0 then swap(f3,f4)`**：**opcode 的奇偶性决定两个操作数的次序**。

### 步骤 50：438 项别名表就内联在 `kn` 里，且恰好映射到 88 个 handler

`bv()` 是个 LCG（`Rb=0x11C0E687, Ry=0x5141, RR=0x535ABF7; Rk[i]=(RR*Ry)%Rb`，34 项），
给出帧的 34 个**数字**键（`vN,vG,vr,vV` = 第 4..7 项 = `70192475, 288282776, 161236508, 37818168`）。
派发表 `kv` 是 `setmetatable({}, {__index=…})`，元方法对 `RW` 做**步长 2 的线性搜索**（`while RR<=0x36C`，即 876/2=438 对）：

```lua
if RW[RR]==v then local Rv=Rz[RW[RR+1]-0x4030FC]
                  rawset(R,v,Rv)  Rf=Rf+1
                  if Rf>=2776 then RY(R) end          -- 固化
                  return Rv end
```

`RW` 的 876 个字面量**完整内联在源码里**，我直接抽出：

- **438 个 opcode 全部互异**；
- `RW[偶数位] - 0x4030FC` 得到的 handler 下标**恰好是 1..88 的 88 个值**（不是 87、不是 89）；
- 别名重数极不均匀：**handler 79 独占 93 个 opcode**，其余多为 1–8 个。

`RY(R)` 是"固化"例程：`while RR<=876 do rawset(R, RW[RR], Rz[RW[RR+1]-0x4030FC]) RR=RR+2 end`
然后 `RW=nil; setmetatable(R,nil)` —— **查满 2776 次后把 438 对全部写死并摘掉元表**，
之后任何对派发表的探测都只能看到一张普通表（反分析 + 提速二合一）。

## 3. 依赖的特征（最重要）

按"抓到它才突破"的顺序，逐条列出我真正依赖的签名/模式：

**A. 结构类签名**
1. **文件结尾的 `}):yq()`** —— 4 个字符决定了整个分析方向。它把"返回一张表"变成"表自调用"，从而确定 `R` = 模块自身，所有 `R:xx()` 都是可命名的方法。**这是第一个也是最重要的支点。**
2. **顶层键的长度异常**：32 个键里 `kn` 独占 260KB（其中 207KB 是 `[=[...]=]`）。"一个函数占了 64% 的体积"直接指认了主体与数据。
3. **`[=[` / `]=]` 长括号**：Lua 长字符串是二进制/大文本载荷的唯一合理容器，一眼锁定。
4. **`(a+b)%v` 形态的数组元素**：`{0XF2,222,0X79,0X84,(0X000C7+0X0004A)%v,(173+82)%v,0X30}` —— 密文字节被拆成"部分明文 + 部分带模运算的表达式"，而模数就是调用点上的形参名。**认出"模数变量名随调用点变化但值恒为 256"** 才让批量抽取成立。

**B. 数字/字母表类签名**
5. **`R[i][j](a,b)` 二维调用形态**：满屏都是，且 `i`/`j` 混用十进制与十六进制（`R[98][0X64]`、`R[0X26][51]`）——**同一槽位的两种写法**是"这是一张固定查找表"的铁证。找到它的定义处 `bk` 就拿到 24 个 `(运算,密钥)` 对。
6. **`bk` 里 24 个槽只有两种形态**（`K1^(b^a)` 与 `a+b-K2`）—— 形态极少意味着可以穷举静态求值。
7. **一张大数字表 + 值域恰为 0..85**：`CU` 拼出的 91 项 `CC` 映射，取值集合是 `{0..85} ∪ {254×5}`。**"值域是连续的 0..N-1 加一个哨兵值"就是字母表/基数系统的签名**，直接读出 base-86。
8. **91 = 83 + 8**：字母表大小 = blob  distinct 字符数 + 标记符号数。这个等式一旦成立，token 化与数字系统就互相锁死。
9. **blob 里"多出来"的字符只有 `[` 和 `~`**，而它们**只出现在 `/9Y<[` 和 `/~4Ha` 内部** —— 用"哪些字符在替换后必然消失"反向验证了标记表是完整的。
10. **`Rv=86; Rk=Rv*0x56; Rb=Rk*86; RX=Rb*0x56`**：连续 4 次乘同一个数 86，是"基数幂表"的经典写法。

**C. 控制流类签名**
11. **`local X=T[Y]; if X then X(...) else break end` + `Xd=Xd+1`**：`kg` 和 `Cx` 里都是这个形态——**认出它就是 handler-VM 调度循环**，是解开字符串解密器和 LZ 状态机的共同钥匙。
12. **一张"handler-id 数组" `RQ` + 一张"id→函数"字典 `Rz`，且两者元素必须一一对上**：我专门把 19 个 id 的十进制/十六进制字面量互相验算（`1709650726==0x65E73326`、`1134708505==0x43A24719`、`1896168820==0x71053D74`、`1734702167==0x67657457`），全部命中才敢确定执行顺序。
13. **`Rb[Rk[9]]=function() v.CW[RR[6]]={0x2A6} ... end`**：赋值目标是 `CW[常量]`，被赋的值是 `{常量}` —— **"一张表被填成 状态→id 映射"** 这个形态一出现，就知道 `CL` 是转移表构造器，`CO` 是 handler 构造器。
14. **`CJ,R.Ct = R.CW[R.Ct], R.Ct+<算出来的1>`**：Lua 多重赋值"先算右边再赋值"的语义 + 常量算出来正好是 1 ⇒ 确认 handler 内部对 `Ct` 的赋值才是真正跳转。
15. **`while Rk<(RR*0X2-RR)-(RR-1)`**：`(0·2-0)-(0-1) = 1`，且该表达式对任意 `RR` 恒等于 1 ⇒ 这是**伪装成条件循环的 `while Rk<1`**，即"跑到某个 flag 置位为止"。opaque predicate 签名。
16. **`+(Rk%2)` 与 `+((Rk%2)-1)` 成对出现在 if/else 两支**：`x%2==0 → +0`，`x%2==1 → +(1-1)=0`，**两支都加 0** ⇒ 恒等噪声。共 4 处。
17. **`local Rv=(R+#RR)%2; return v+Rv-(R%2)`**：因 `#RR=10` 是偶数，`(R+10)%2 == R%2` ⇒ **整个函数就是 `return v`**，一个恒等 decoy。共 5 处这个形态。
18. **`if (Rf%2)==0 then <A> else <A'> end` 且 A 与 A' 逐字符等价**：`Rf` 是环境指纹但**不影响结果** ⇒ 反篡改诱饵。这个判断让我确认 SBOX 是确定性的、可以离线重建。
19. **`repeat <赋值> break until false`**：45 处。就是 `if not X then X=... end` 的膨胀写法，是 Kryvex 的固定填充模式，看到就知道可以整段折叠。
20. **`RW[0x1569711]=function(R,...) if R and RW~=RO then return 0x156C811 end ...`**：`RW`/`RO` 两张表互相比身份（`RW~=RO`）——这是**双表 trampoline**，用来隐藏"最终只是调 `RZ(...)`"。认出它就不必逐状态跟。

**D. 语义/字符串类签名（已知明文攻击的锚点）**
21. **`Rt(b, {[6字节串]=[1字节串]})` 且 `Rt` 是 12 字节串** ⇒ 只可能是 `setmetatable(t, {__mode="k"})`。**"12/6/1 字节 + 双参数调用 + 弱表语义"三者交叉锁定**，这是校准字符串解密器的决定性锚点。
22. **`Rz[name]` 被无参调用且结果被当作全局表** ⇒ `getfenv`（7 字节，数组恰好 7 项）。
23. **`(Rb and Rb[R[4字节]]) or (Ry and Ry[R[4字节]])` 且 `Rb` 是 5 字节、`Ry` 是 3 字节** ⇒ `bit32.band / bit.band` 双回退。**"5 字节名 + 3 字节名 + 4 字节成员名"的长度三元组**直接给出 `bit32`/`bit`/`band`。
24. **`Rk(RR,4,4)..Rk(RR,7,7)..Rk(RR,2,2)..Rk(RR,3,3)..Rk(RR,5,5)`**：对 `tostring(function() end)`（形如 `"function: 0x..."`）按位置 4,7,2,3,5 抽字符 = `"count"` ⇒ 目标是 `collectgarbage("count")`。**用字符位置反推出被隐藏的字符串**，这是环境指纹逻辑的签名。
25. **`string.find(errmsg, ":".."\2"..":")`**（由 `Rb(0x3A)..(0X2)..Rb(0x3A)` 拼出 `":2:"`）+ `pcall(function() local RR; return RR() end)` ⇒ 在探测 Lua 报错文本里的 `file:line:` 形态。
26. **`Rv(0x7E,0x18),Rv(0x6D,0x18),...` 连续 XOR 同一密钥 0x18** ⇒ 解出 `"function"`/`"string"`/`"find"`。**连续同密钥单字节 XOR 是最弱的字符串签名**，它让我在还没有解密器时就先自证了 XOR 读法。
27. **`debug.getinfo(f,"S")` 后比较 `what=="C" and source=="=[C]"`** ⇒ 反 hook：在 `loadstring/load/getgenv/getrenv` 候选里**优先挑 C 实现**，被 Lua 层 hook 过的会被识破。
28. **`'for' initial value must be a number` / `'for' limit must be a number` / `'for' step must be a number`** 三条串同时出现在 `kn` ⇒ VM 有一个 FOR/循环 opcode，且它**自己复刻了 Lua 解释器的报错文本**（用来在被篡改环境里保持行为一致）。
29. **`KryvexObf_` 前缀 + `kryvex`（chunk 名）+ `1%@`（作者）+ 文件头注释 `--Kryvex,by 1%@`** ⇒ 四处独立来源互证混淆器身份。

**E. VM 层签名**
30. **`if R<128 then yI=Rd[R] else yI=RL[R-127] end`**（及其 `>127 / -0x7F` 变体，多处重复）⇒ **操作数编码规则**：≤127 是寄存器 `Rd[]`，>127 是常量池 `RL[op-127]`。**这一条是整个 VM 语义的钥匙。**
31. **`Rv=Rv+3` / `Rv=Rv+b` 出现在指令体末尾** ⇒ PC 推进量 = 指令长度；定长 3 的是 ALU 类，变量的是跳转类。
32. **`RX[#RX+1]={yI}` 与 `RX[#RX]=nil` 成对** ⇒ 存在一个**操作数栈**，且每个槽是 1 元素表 `{value}`（装箱，为了引用语义）。
33. **`RS[Rv]` 后紧跟 `Rb[1],Rb[2],Rb[4],Rb[3]`** ⇒ 指令是 4 元组，且**取用顺序被打乱**（1,2,4,3）以混淆操作数角色。
34. **`kv` 的 `__index` 元方法里 `while RR<=876 do if RW[RR]==v then ...`** + **`Rf>=2776 then RY(R)`（用 rawset 填平并 `setmetatable(R,nil)` 摘掉元表）** ⇒ opcode 查表是**线性搜索 + 用满次数后自我固化**的反探测设计。
35. **`RR[Rg][-0x790F8114] = (Re + op*0xED75 + A*0x81A5 + C*0x1B49 + B*0xB5E3) % 2^32`** 每条指令都累加 ⇒ **执行轨迹完整性校验和**。
36. **`RQ=(RO*0xB974)%RG`，`RO=(RO*RD+op+A*Rq+C*Rp+B*RT)%Rh`，真实 opcode = `Rd-RQ`** ⇒ **opcode 每条指令滚动重映射**。
37. **438 个 opcode 值只映射到 88 个不同槽位** ⇒ 多对一别名表，同一语义有多个 opcode 编码（多态 dispatch）。

**F. 第二轮新增签名（这几条是本轮真正打开局面的，越具体越好）**

38. **形参表以 `_` 开头且出现重复 `_`（`function(_,R,_)`、`function(_,_,_)`），调用一律冒号形式** ⇒ **self 占用第 1 个形参**。这是本轮最关键的一条：补上这一层之后，`yc/ye/Cu/kF/bk/kI/kd/yS/yJ/bR` 十个函数原本"对不上"的实参绑定**同时全部自洽**。反过来它也是极强的校验器——任何一处绑定错，都会立刻产生"对字符串取 `#`"、"调用数字"、"索引函数"这类不可能成立的表达式。
39. **`local Rv=function(R,v) local Rv=(R+#RR)%2 return v+Rv-(R%2) end`，而 `#RR==10` 是偶数** ⇒ **`Rv(R,v) ≡ v`，恒等函数**。`CL`/`CO`/`ye` 里几十处 `Rv(0X1CE2,RR[1])`、`Rv(28860,RR[4])` 因此**全部塌缩成第二个实参**。不识别这一点，就会把 `CW` 误读成"键高达 63212 的稀疏表"、把初值 `Ct` 误读成 7392。这是典型的"用无意义算术包裹常量"手法。
40. **`CW` 恰好 10 项、`CE` 恰好 13 项，且 `CE` 的键公式是 `CQ+(code+CS)*Cz` 而 `CS=0xD=13`** ⇒ 转移表与 handler 表用同一个 `code` 串起来。解出的 10 个 code `{428,146,760,1037,296,809,310,546,961,678}` 与 `CO` 里 13 个 `(0X40D+13)/(0X1AC+13)/(296+13)/(546+13)/(0X329+13)/(0X136+13)/0X9EC/(0X92+13)/(0X2A6+13)/(0X2F8+13)/(961+13)/0X1D44/0X1FE4` **一一对上**，多出来的 3 个是 `function(_) end` 空 handler（decoy）。**这种"两张表必须闭合"的关系是最强的自校验。**
41. **`yn` 首行 `if C.Cv and C.Ck>0X7 then return 0XFF end` 位于 `if #X>0`（缓冲弹出）与 `if R>C.Cf`（终止）之前** ⇒ Stage 2 的控制字节**既不消耗输入也不推进游标**。再配合"每 4 个字面量恰好耗尽一个 5-token 组、每 8 个字面量恰好把 `Ck` 推到 8"，可**证明**缓冲区永远不会被这条捷径跳过 ⇒ **Stage 2 是纯字面量流**。这一条把"part2 是否也是 LZ 压缩"这个疑问彻底关掉了。
42. **`RI` 的键解出来是 {4, 26, 56, 44, 228}，而 `RI` 被 `RI[(RS())]` 索引** ⇒ 键必须 ∈ [0,255]，5 个全部命中。**更强的**是 `RN` 的键解出来是 {4, 26, 56}（+decoy 218），而 `RN` 被 `RN[(Rv[1])]` 索引，`Rv[1]` 来自 `RA[..]={0X04,...}` / `{0X01A,...}` / `{56,...}` ⇒ **常量类型码与 handler 键三方一致**。这是 `bk` 解码正确性的独立证明（不依赖 `kI` 的 1..8 那条）。
43. **`bR` 用 `kg` 解码器生成 58 个字符串，再写 `b[<hash>] = _ENV[<字符串>]` / `math[...]` / `string[...]` / `table[...]` / 字面串** ⇒ 只要把 `kg` 破了，**整个运行时环境表就能静态解出来**（46 条）。这是把"环境相关"变成"环境已知"的关键——正是它让我确定 `Ry[0x2267BA0C]="number"`，从而证明 `kF` 的 `RZ` 是纯常量。
44. **`kH` 里 `local Rv=v.kP; local Rz=Ry+v.kQ; while Rv<Rz do ... v.kM[Rv] ...`，而 `kd` 里写的是 `v.kM[Rb+Rk]`（`Rk=v.kP`、`Rb`=1..kQ）** ⇒ **两个不同函数对同一对 (基址, 条数) 的用法互证**：`kP` 是指令区基址、`kQ` 是条数。由此 `kQ ≤ 7461` 成为硬 oracle。
45. **`kd` 的返回值被赋回 `RV`（`RV=R:kd(...)`），且状态 12057 末尾再次覆写 `RV`** ⇒ **`RV` 是分代的**：头部 `kE/kz/kP` 用 RV₁，`Rh` 用 RV₂，`nChild` 用 RV₃。任何把 `RV` 当常量的实现都必然错。
46. **`RV` 完全不出现在 `RS()` 的任何一条算式里** ⇒ 整条 119405 字节密钥流与 `RV` **无关**，可以预先算一次，把 `RV` 变成能独立穷举的自由变量。同理 `kI` 的四个状态字与 `va` **都**只是中间量 `Ry` 的函数（`Rc=B2[0]^Ry`、`RF=B2[1]`、`Ru=B2[2]^(Ry>>16)`、`Rx=B2[3]^(Ry>>24)`、`va=((Rf2+Rc·65537+RF·257+Ru·17+Rx) mod 0x7FFFFFFE)+1`），而 `Ry` 与 `RV` 又都是 `RZ` 的函数 ⇒ **真实的 (Ry, RV) 落在一条由 `RZ` 参数化的一维曲线上**。这三条"降维"观察是把 2^64 的联合空间变成可穷举的唯一途径。
47. **`kQ = Rw₅ ⊕ rotl(kE,11) ⊕ rotl(RV,7)` 且 `kE = Rw₁ ⊕ RV`** ⇒ `kQ = T ⊕ M(RV)`，其中 `T = Rw₅ ⊕ rotl(Rw₁,11)` 已知、**`M(x)=rotl(x,11)⊕rotl(x,7)` 是 GF(2)-线性映射**（`M = rotl7∘(I+rotl4)`，多项式 `1+z⁴` 与 `z³²−1` 的 gcd 为 `(1+z)⁴`，故核维数 4、像的大小 2^28）。因此"kQ 小"这个约束可以**直接解线性方程组**而不必扫 2^32：对每个目标 `T⊕kQ` 要么无解要么恰有 16 个解。实测一级筛出 7472 个候选，与理论值 7462 吻合——**理论与实测对上了，这本身就是对整套转录的验证**。
48. **`kI` 里 `RC=({})[0XED0E22] RX=({})[0X55B5CD] Rs=({})[0X98E805] Rj=({})[0XFD3D44]`（索引空表 ⇒ 全部置 nil）** ⇒ 用完即焚的反取证：把 8 项密钥数组在构表后立刻抹掉，阻止内存快照/静态读取。
49. **`vu()` 状态 12057 里 `local _,RD,RA,Rm,Rc,Rx,Ro,RZ,Rp=R:yo(...)`** ⇒ 用与 `kn` 顶层**同名的局部变量**遮蔽 `Rm`（字节游标）、`Rc`/`Rx`（密钥态）。因为 `RS()`/`vf()` 是 `kn` 层的闭包、捕获的是 `kn` 层的上值，这些遮蔽**对密钥流毫无影响**，纯粹是给读者的陷阱。识别它需要严格区分"定义点作用域"与"调用点作用域"。

**G. 第三轮新增签名（本轮打穿字节码所依赖的、最具体的几条）**

50. **`kI` 头部 `local RR,Rv,Rk=0X100000000,0X100,0X6A`，而 rekey 四行写作 `k=v(k,Ry%Rv) b=v(b,X(Ry/Rv)%Rv) y=v(y,X(Ry/0X10000)%Rv) C=v(C,X(Ry/0X1000000)%Rv)`** ⇒ **`Rv` 在 `kI` 体内等于 256，不是 2^32**。这是整个攻击的**根因签名**。判据非常干净：`kI` 返回的 `k,b,y,C` 会直接喂给 `RS()` 的 `RR[44]/RR[96]/RR[12]/RR[40]`，而那四个闭包里全是 `rotr8(...)` 与 `%0X100` —— **值域必须是字节**。任何让 `Rc` 变成 u32 的读法都与下游矛盾。附带地：`Rf` 内部另有 `local Rv,Rk=0X100000000,0X10000`，是**函数体内的第二层遮蔽**，两层必须分开读。
51. **`kI` 里 `local Rj=R[38][0X32]`，随后 `Rb[Rk]=(Rj(RC[Rv],RX[Rv])+0X243DB52F+0XDBC24AD1)%RR`** ⇒ 组表用的是 `bk` 的**异或槽**（key `0x1EDBF73`），不是裸异或。判据：`Rs` 数组（8 项）必须恰好是 `{1..8}` 的**排列**，因为它是 `Rb` 的键集；实测 `[3,1,6,7,8,2,4,5]` ✓。**"必须构成排列"是一个不可能被巧合满足的自检。**
52. **`yc=function(y,C,v,R,b,k,X,s,j,f)` —— 第一个形参名不是 `_`** ⇒ 38 个方法里**至少有一个**不遵守"`_` 占位"约定，但 `:` 语法仍然把 self 绑上去。识别方法：`yc` 的返回式里有 `f(C, s[0x7B][0x63](924433702,874119316))`，把这个 `bk` 常量算出来是 **1**，于是 `f` 必须是"接受 (串, 1) 的函数" = `string.sub`，而 `string.sub` 正是调用点传进来的第 9 个实参 `kX` ⇒ **反推 `f`=第 10 个形参 ⇒ self 占了第 1 个 ⇒ `y`=对象、`C`=blob**。**用常量的语义反推形参对位**，这一招在这里是决定性的。
53. **`kH` 的校验和种子 `R(R(R(R(899760,0XB9559),3513384928),(C==0 and y[0X79FA2C07] or C==1 and y[0X679BA927] or C==2 and y[0X5083305B] or y[0X5053C894])),v.kE)`** ⇒ 四个 hash **不在** `bR` 恢复的 46 条环境表里，必须全文检索找写入点；写入点在 `kG`/`yD`/`ki`/`ku` 四个方法体尾部的 `s[a],s[b],s[c]=X,Y,Z` 三元赋值里，且 `s` 就是环境表。判据：这四项要参与**异或**，所以必须是**数值**而非闭包 ⇒ 只能取各方法**体作用域**里那个同名的数值局部量（形如 `local Rb=b(X(y[R[0x6F][0x51](A,0x1F582F6A)],(C*0xD3B7+0x51B8D476)%2^32),kk,R[i][j](u,v))`）。四者的 `kk` 恰好是 **0/1/2/3** —— 这个"整齐到不像巧合"的分布本身就是读对了的证据。
54. **12057 末尾 `RV=RX(RX(Rd(RV,0X7),Rd(RE,0XD)),RX(Rs,RR.kE))`，而 `Rs` 在循环里被 `RI` 处理器改写（`Rs=(Rs*0X1F+Rx(RU,R-1,Rb,Ry)+1)%2^32`），且 `Rx`=`yo` 的哈希闭包、`RU`=`yD` 的解码输出** ⇒ **RV₃ 被一条需要整个常量解码子系统才能算的链污染**。绕开它的签名是下一条。
55. **`nChild = Rw() ⊕ rotl(kE,15) ⊕ rotl(RV₃,5)`，且 keystream 与 `RV` 完全无关（签名 46）** ⇒ **`RV₃ = rotr32(Rw₄ ⊕ nChild ⊕ rotl(kE,15), 5)` 是 `nChild` 的双射**。于是"求被污染的 RV₃"被**等价改写**成"枚举孩子个数"，而孩子个数又被子原型的合法性（`kQ` 上界、`RH<4`、操作码 100% 命中）唯一确定。**这不是启发式搜索，是精确反解。** 配套的两个工程要点：(a) keystream 与 `RV` 无关 ⇒ 孩子头部只需**读一次**，其余候选纯算术判定（531 s → 186 s）；(b) `n=0` 必须**最后**试，因为它没有孩子可验证，任何 RV₃ 都会"通过"。
56. **`kH` 的槽位写入 `local Rk=(RR*0X4003+0XEDD533+v.kz)%k` 与 `RI` 处理器的 `local Rv=((R-1)*0X4003+0XEDD533+RR.kz)%Rk` 是同一个仿射映射** ⇒ 常量表 `RA` 与寄存器值表 `Rb`/校验表 `Rj` **共用一张散列地址空间**，键 = `(index*0x4003 + 0xEDD533 + kz) mod 2^32`。`0x4003` 是**奇数** ⇒ 模 2^32 **可逆** ⇒ 每个键都能**唯一反解**出 index。实测 2336 个键反解后 1684 个落在 <2^20，且寄存器使用直方图在 **0..15 处出现峰值** —— 这是一张真实寄存器文件的指纹，且反解是唯一的，不是拟合。
57. **`yD` 的 `Rr(y,R,k,b,C,X)` 里出现 `RW={2^40,2^32,2^24,2^16,2^8,1}`、`Rf=1-2*((RR[8]-RR[8]%0x80)/0x80)`、`RU=(RR[8]%0x80)*0x10+(RR[7]-(RR[7]%0x10))/0x10`、`if RU==0x7FF then return Ry==0 and Rf*(1/0) or (0/0)`、`return Rf*(Ry+2^52)*2^(RU-0x433)`** ⇒ **这是一个逐位重建 IEEE-754 double 的解码器**（`0x433`=1075=bias+52，`0x7FF`=指数全 1 ⇒ ±inf/NaN，`2^(-1074)` ⇒ 次正规数）。因此 `RI[26]`/`RI[56]` 那两个 8 字节块的**语义已经确定：它们是双精度浮点常量**（虽然还要先过 `Rr`/`RG` 的置换与异或层）。
58. **`yD` 里 `local RO={{Rj,16,1,6},{4,8,14,13},{11,12,3,15},{10,9,7,5},{4,16,7,15},{Rj,9,3,13},{10,12,14,6},{11,8,1,5}}` 配合 `for _=1,5 do for Rv=1,#RO do ... Q(...)`，以及 `Rj` 由 `f[Rb][(Rb-Rb%RU)/RU]`（对数/反对数表）构建成 256 项** ⇒ 常量解码层是一个 **GF(2^8) 上的 5 轮分组密码 + 动态生成的 S 盒**（`{4,8,14,13}` 一类四元组正是 GF(2^8) 乘法表的行列片段）。**这一层是本轮明确没有实现的部分**（见 §5.1）。


**H. 第四轮新增签名（第 4 层常量密码）**

59. **`yD` 形参表 `(_,R,s,b,y,C,X,j,v,f,Q,z,d,k,U,M,_,_,L,W,O,E)` 里第 10 位 `f` = `vz`（`yJ` 的第一返回值 = 256×256 表）** ⇒ 代码里所有 `f[a][b]` 都是**异或**，所有 `f[x][y]` 形式的"查表"其实是 `x xor y`。不识别这一点，会把 `Rj` S 盒的构造 `Rs=f[Rb][(Rb-Rb%RU)/RU]` 误读成 GF(2^8) 对数表（我第一遍就误读了，见 §5.5 撤回 (i)）。**判据**：`yJ` 里那张表是用"逐位异或"的循环填的，`Rv[Rk][Rv]=RC` 且 `RC` 由 `if Rv~=Rk then RC=RC+RX` 累加 —— 那就是异或表。
60. **`RE` 的两个分支：分支 B 是 `Ry[i]=(RN[i]+0xD5874D67)%2^32`，而 `RN[i]` 的定义是 `(分支A的常量 + Rk)%2^32`，且 `Rk=0x2A78B299`** ⇒ **`0x2A78B299 + 0xD5874D67 = 2^32 ≡ 0`**，两分支逐字相同；再用 `bk` 把分支 B 的 4 个覆写下标解出来正好是 `{b:6, y:5, v:15, C:13}`，与分支 A 的固定位置一致。**这是"反篡改分支其实是 decoy"的最干净的一条证据**——两个魔数相加恰好等于模数，绝不可能是巧合。
61. **`yF` 的 `Rk(R,v,k,b,C)` 里 `local Rk=((R[v]+y)%2)` 后接 `for Rb=1,2 do if((Rk+Rb)%2)~=Rk then RR(...) else Rv(...) end`** ⇒ `Rb=1` 恒走 `RR`、`Rb=2` 恒走 `Rv`，**与 `y`(=`vX`) 无关**。展开后旋转量是 **16/12/8/7**、加法常数是 `0x17F89CED`/`0xE8076313` ⇒ **Salsa20/ChaCha 的 quarter-round**；8 个轮索引四元组是 ChaCha 列轮+对角轮的下标置换；跑 5 轮。**认出"旋转量 16/12/8/7"这一个特征就把整个密钥扩展定性了。**
62. **`RK`/`RB` 的"每 64 字节块前 8 字节不异或"掩码，前后各出现一次，中间夹的 `Rz` 是纯异或流，且 `#R == #Rk`** ⇒ **掩码自相抵消**。同理 `RG`/`Rr`（源码里甚至显式写了两次 `v(...,(RU+RR*0x3D)%Rv)`）。**推论：`RK` 与 `RB` 只差轮键 `RA` vs `RI`，`RG` 与 `Rr` 只差 `Rt` vs `RH`**；两组不同的加法常数（`0x6987824E/0x757B/…` vs `0xC555984B/0x39E7/…`）与两个不同步长（`0x67` vs `0x85`）**全部无效**。这一条把要暴力尝试的自由参数从 8 个砍到 4 个。
63. **`local RU=#Rk; local RC=""; local Rb=RU; while Rb>0 do RC=U(Rk[Rb])..RC  Rb=Rb-1 end`** ⇒ 循环变量**递减**而拼接是**前插**，结果是**升序**（不逆序）。这是一个纯粹的读码陷阱：**"递减 + 前插" = 正序，"递增 + 前插" 才是逆序**。我用"`idx` 必须是 `0..Rh-1` 的排列"这条 oracle 做了 96 变体暴力才确认（步骤 39）。
64. **`Rr` 末尾 `RW={2^40,2^32,2^24,2^16,2^8,1}`、`Rf=1-2*((RR[8]-RR[8]%0x80)/0x80)`、`RU=(RR[8]%0x80)*0x10+(RR[7]-RR[7]%0x10)/0x10`、`if RU==0x7FF …`、`return Rf*(Ry+2^52)*2^(RU-0x433)`，配合 `RP={5,7,6,1,3,4,2,8}`** ⇒ **IEEE-754 binary64 的逐位重建**：`RP` 是把 8 个字节按 (5,7,6,1,3,4,2,8) 重排；`RR[8]` 的 bit7 是符号、低 7 位是指数的低 7 位，`RR[7]` 的高 4 位是指数的低 4 位、低 4 位是尾数最高 4 位；`0x433`=1075=bias+52，`0x7FF`=指数全 1 ⇒ ±inf/NaN，`2^(-1074)` ⇒ 次正规数。**这条让我在没有解出任何数值之前就断定了 8 字节块的语义是 double**，随后解出的 `180.0 / 44.0 / 0.5 / 0.16 / 0.33` 印证了它。
65. **`yo` 的 `Rf` 闭包里 `if y(X)~="string" and y(X)~="table" then X=s..(X or 0) end`，而 `s` = `vu` 12057 的 `RG` = `RP[RU]` = `RB({0x28,0xF6,0x6B,197,0x5B,0x6F,0x37,0x84,0xFB,0x45}, 0x193)`** ⇒ 用第一轮的 `kg` 解码器解这 10 个字节得到 **`'KryvexObf_'`**，正是第 1 步从文件里直接认出的全局前缀。**两套独立 machinery 在同一个字符串上闭合**，是 `yo` 实参绑定正确性的强验证。
66. **`_Rv = RX(Rw(), RX(Rs, RX(rotl(kz,(RQ%13)+1), (RQ*0x4003)%2^32))) + 1`，且 `RI` 处理器把常量写到 `RA[((R-1)*0x4003+0xEDD533+kz)%2^32]`** ⇒ 每个原型的 `Rh` 个常量各占一格，**所以 `idx = _Rv-1` 必然是 `0..Rh-1` 的一个排列**。这是一条**免费且极强**的 oracle：`Rs` 链任何一步算错，下一个 `idx` 立刻变成 32 位随机数（落回 [0,Rh) 的概率 ≈ `Rh/2^32` ≈ 5e-8）。本轮就是靠它把 bug 精确定位到"第 15 个常量"。


**I. 第五轮新增签名（四套平行解码器的识别与验证）**

67. **`yD` 的每个特征常量在全文 `total_in_file = 1`，但 `0X17F89CED`/`0XE8076313` 也只出现 1 次且落在 `yF` 里** ⇒ **先用"常量出现次数"探针判断哪些是共享、哪些是每方法独有**，再决定实现策略。结论：quarter-round（`yF`）与 PRF（`kI` 的 `Rf`）四套共享，其余约 25 个字段每套独有 ⇒ "1 份通用实现 + 4 份 spec"，而不是 4 份实现。
68. **四个方法头部的 `Rk` 与各自密钥扩展里分支 B 的加法魔数，两两相加都恰好等于 `2^32`**：`0x1C4FDC79+0xE3B02387`、`0x2A78B299+0xD5874D67`、`0x26A93733+0xD956C8CD`、`0x31AE5723+0xCE51A8DD` 全部 `=0x100000000` ⇒ **四个"依赖 `vX`=`collectgarbage("count")` 的反篡改分支"全部代数恒等**。一次是巧合，四次是设计意图：**把宿主运行时指纹接进一个恒真分支**，让人误以为存在静态不可知的输入。这条也彻底关闭了"Stage 2 依赖宿主环境"这个假设。
69. **分支 A 里 `y/b/C/v` 四个形参出现的位置，必须等于分支 B 用 `bk` 从另一组字面量算出的 4 个覆写下标**（kG `{y:2,C:3,b:7,v:10}`、yD `{y:5,b:6,C:13,v:15}`、ki `{y:8,v:11,C:14,b:15}`、ku `{C:2,v:4,b:14,y:16}`）⇒ 这是**对 8 个独立常量抽取结果的交叉验证**，四份 spec 全部命中。同类自检还有三条：`T8` 的 8 个键必须恰好是 `{1..8}`；S 盒 256 项必须是 `0..255` 的排列；散布表 16 项必须恰好是 `1..61` 中 ≡1 (mod 4) 的那 16 个。**四条都是"不可能被巧合满足"的离散结构约束。**
70. **同一个 `ENV` 值可以从两处完全独立的代码位置抽出并互相验证**：第三轮从 `kH` 的 RC 种子
    `(C==0 and y[0X79FA2C07] or C==1 and y[0X679BA927] or C==2 and y[0X5083305B] or y[0X5053C894])`
    抽出的四个值，与第五轮从四个方法体作用域的 `local Rb=/local Ry=` 抽出的四个值**逐个相等**
    （`0xA6AF8F6A / 0x4B3103A2 / 0x4493EE32 / 0x096B79C6`），且 `kk` 恰好是 0/1/2/3 与 `RH` 的 4 路一一对应。
71. **数值派发器的奇偶方向在四个方法里不一致**：`yD`/`ku` 是 `if((R or 0)%0X2)==0 then RG/RV else Rr/RK`，
    而 **`kG`/`ki` 是 `if((R or 0)%0X2)~=0 then …`（反向）**。字符串派发器四个都是 `==0`，但偶分支分别走
    `RK`/`RY`/`RB`/`RB`。**照抄一份的奇偶映射到另一份必然全错**，而错法很隐蔽：解出来的仍是可打印字节，
    只是 `Rx` 哈希错 ⇒ `Rs` 链崩 ⇒ 下一个 `idx` 变随机数。**所以"`idx` 必须是 `0..Rh-1` 的排列"这条 oracle
    在这里第二次救了命。**
72. **最终的整体 oracle：25/25 个原型的 `RV3`/`nChild` 全部由纯前向计算得出（反解回退 0 次），且字节预算精确闭合 119409/119409。** 四份 spec 合计约 100 个手工抽取的常量，任何一个抽错都会让对应原型的 `Rs` 链崩塌、`idx` 变成 32 位随机数、`nChild` 超界。**"全部 25 个都过"是比任何单元自检都强的验证。**


**J. 第六轮新增签名（第 5 层：解释器与指令编码）**

73. **主循环里 `local Rd=RC+RQ` 紧接 `local Rz=kv[Rd-RQ]`** ⇒ **恒等于 `kv[RC]`**。配合 `RQ=(RO*0xB974)%64414`、`RO=(RO*0xFF+f1+f2*60+f4*50+f3*62)%2^32` 这套"每条指令滚动重映射 opcode"的机械，**派发结果与滚动量完全无关**。这是本样本第 5 处"看起来在做事、实际恒等"的构造。**识别方法**：看到 `x = a + K` 后紧跟 `t[x - K]`，先怀疑是 decoy。
74. **`yL` 里三个数组的解掩码键与 `kd` 的三层存储掩码一一对消**：`kd` 存 `kL[i] = (…) ⊕ (kz⊕kP)`，`yL` 用 `bxor(C[yA], kT)` 而 `kT = Rx = kP⊕kz`；`kd` 存 `kW[i] = (…) ⊕ kP`，`yL` 用 `bxor(j[yA], kh)` 而 `kh = Rc = kP`；`kd` 存 `kO[i] = (…) ⊕ kz`，`yL` 用 `bxor(s[yA], ka)` 而 `ka = RK = kz`。而 `kM` 在 `yL` 里**不异或任何键**（`RO=X[yA]` 直接进 `RL`）。⇒ **四个数组到 `X/C/j/s` 的映射可以用代数唯一确定，不需要试 24 种排列**。（`Rq=kP⊕kz, RK=kP⊕Rq=kz, Rc=Rq⊕kz=kP, Rx=Rq` 这四个化简是钥匙。）
75. **`yL` 头部 9 个"大魔数"全是三层 bxor 包裹的小整数**：`Ry=65537, RC=17, Rv=256, RX=257, Rs=4097, Rj=17881, Rb=2, Rf=3`。⇒ 滚动密钥其实是 `yH = (yH*3 + (f1-b)*257 + RQ*4097 + f3 + f4*17) mod 2^32`，最大中间积 1.76e13 < 2^53，**double 精确**。而 **`Rb=2` ⇒ `if f1 % 2 ~= 0 then swap(f3,f4)`**：**opcode 的奇偶性决定两个操作数的次序** —— 这是指令格式里最容易被漏掉的一条。
76. **`RW` 的 876 个字面量完整内联在 `kn` 里，步长 2 读**：奇数位是 opcode，偶数位减 `0x4030FC` 是 handler 下标。抽出后 **438 个 opcode 互异、handler 下标恰好铺满 1..88**（不多不少），且重数极不均（**handler 79 独占 93 个 opcode**）。**"恰好铺满 1..88"是一条不可能巧合的离散自检**，它同时验证了 `0x4030FC` 这个偏移和整张表的抽取。
77. **`if Rf>=2776 then RY(R) end`，`RY` 做 `while RR<=876 do rawset(R,RW[RR],Rz[RW[RR+1]-0x4030FC]) RR=RR+2 end` 然后 `RW=nil; setmetatable(R,nil)`** ⇒ **查满 2776 次后把 438 对全部固化、抹掉别名表、摘掉元表**。运行前后派发表的结构完全不同（这是"自我固化"型反探测），也意味着**动态 dump 派发表比静态读更容易**——但我们纯静态，所以直接从内联字面量抽。
78. **`f1` 必须命中那 438 个值**是第 5 层的硬 oracle：命中率若错则 `438/2^32 ≈ 1.02e-7` 每条，6096 条全中的概率 ≈ `10^-42000`。实测 **6096/6096 = 100%**。这条 oracle 一次性验证了 `yL` 的 9 个常量、`yH` 初值、3 状态机次序、条件交换、以及四个数组的角色映射——**约 20 个独立转录点同时被验证**。
79. **`RS` 的 `__index` 元方法是惰性的**：`while RF.yA<pc and RF.yA<kP+kQ do Ri() end; return rawget(t,pc)` ⇒ 指令是**按需**从 `kM/kL/kW/kO` 解出来的，且 `yH` 是**跨指令滚动**的。所以**不能随机访问**：想解第 *n* 条必须先解前 *n-1* 条。任何"直接按下标取指令"的实现都会错。

### 4.6 VM 指令语义（第 3 层）

**指令格式**：`RS[PC]` 是 4 元组，取用顺序被打乱为 `Rb[1],Rb[2],Rb[4],Rb[3]` → `(opcode, A, C, B)`。

**操作数编码**（关键规则，多处重复出现）：
```lua
if op < 128 then val = Rd[op]        -- 寄存器
else             val = RL[op-127]    -- 常量池
end
```

**派发循环**（`kn` 内 `Ru(...)`，逐字还原）：
```lua
local function Ru(...)
  while Ru ~= RZ do
    RJ = true
    local n = Ry[0x7036BF33]                       -- 计数器 = 59 + hash(tostring(env))%17
    if RM and n > 0 then n = n-1; Ry[0x7036BF33] = n end
    if RM and n > 0 then RQ = RO % RG else RQ = (RO * 0xB974) % RG end   -- 滚动 opcode 偏移
    local oldPC = Rv
    local ins   = RS[Rv]                            -- 取指
    local op,A,C,B = ins[1],ins[2],ins[4],ins[3]
    Rv = Rv + 1
    RR[Rg][-0x790F8114] = (Re + op*0xED75 + A*0x81A5 + B*0x1B49 + C*0xB5E3) % 2^32  -- 轨迹校验和
    local key  = op + RQ
    local h    = kv[key - RQ]                       -- kv 带 __index，线性搜 438 对；用满 2776 次后自我固化
    local call = h or RV
    local r1,r2,r3,r4 = call(op, A, B, C)
    if r1 == true then done = true                  -- 约定：返回 true ⇒ 函数返回
    else Rv = r1; done,_,_ = r2,r3,r4 end           -- 否则 r1 = 新 PC
    Re = (Re + (Rv-oldPC)*0x5189) % 2^32
    RO = (RO*RD + op + A*Rq + B*Rp + C*RT) % Rh     -- 推进 opcode 重映射
    if done then
      local m = RR[vR]
      if m == 1 then return RR[vv]
      elseif m == 2 then return vj(RR[vv], RR[vE], RR[vQ]) end
      return
    end
    if RJ and Rv > vm then vm = Rv + 0x6981; Rx,Rc,RK = ky(...) end
    RJ = false
  end
end
return Ru(...)
```

### 4.7 防御 / 反调试 / 反篡改逻辑（全部还原）

1. **`debug.getinfo` C 函数指纹（`ye!Rd`）**：对候选 `loadstring/load` 逐个执行
   `pcall(debug.getinfo, f, "S")`，要求 `type(getinfo)=="function"`、`type(info)=="table"`，
   最终判定 `info.what == "C" and info.source == "=[C]"`。**优先选择 C 实现的加载器**——若攻击者用 Lua 包装 hook 了 `loadstring`，`what` 就不是 `"C"`，会被跳过。
2. **`tostring(function() end)` 地址指纹（`kg` 与 `kF`）**：`pcall(tostring, function() end)`，再对它按位置 **4,7,2,3,5** 抽字符拼成 `"count"`，调用 `collectgarbage("count")`；把地址串与 GC 计数一起哈希进 `Rf`/`Rk`。**用字符位置拼接来隐藏 `"count"` 这个字符串常量。**
3. **报错文本指纹（`kg`/`kF`/`yq`/`kD`/`kV`/`kp`）**：`pcall(function() local RR; return RR[1] end)` / `RR()` / `RR(1)`，对返回的错误消息逐字节哈希（`Rf=(Rf*0xB49D+byte)%0x7FFFFF01` 等）。**借此区分 Lua 5.1 / 5.2+ / LuaJIT / Luau**，因为 `"attempt to index a nil value (local 'RR')"` 这类文本各实现不同。
4. **`string.find(msg, ":".."\2"..":")`（`yq`/`kV`）**：在报错文本里找 `":2:"`，即 `file:line:` 形态，验证错误消息来自真实解释器。

### 4.12 内层流密码 `RS()` —— 完整去混淆后的算法（本轮逐字三次核对）

### 4.14 VM 指令流（6096 条，已解密）

每条指令是 **4 元组**：`F1` = `Rw()` 的无符号 32 位字，`F2/F3/F4` = `kj()` 的有符号 32 位字。
`F1` 的**最高 2 位决定该指令后面额外跟几个密码字节**（`kd` 里 `Rz=((F1-(F1%2^29))/2^29)%4`，
然后 `for _=1,Rz do RR=(rotl(RR,3)+RS()+0x3D)%2^32 end`）。全表见 `analysis/stage2_instructions.txt`（425 KB）。

`kd` 把这 4 个原始字段与滚动密钥 `RRr` 混合后写入 `kM/kL/kW/kO`：

```
kM[i] = F1 ⊕ kz ⊕ (RRr mod 2^28)
kL[i] = ((F2 mod 2^32) ⊕ rotl(RRr,5) ⊕ kE) ⊕ (kz ⊕ kP)
kW[i] = sgn( xor( xor(F2', kM[i]), xor(rotl(RRr,11)⊕L1, rotl(RRr,17)⊕kE⊕... ) ) ) ⊕ kP
kO[i] = 同上, 用另一组常量 ⊕ kz
RRr   = (rotl(RRr,7) + kM[i]) mod 2^32 ⊕ (F2 的混合值)
其中 L1=589742⊕0x720EE⊕0xC33D6FB1, 0x10599⊕0x8B73⊕4132475171, 152743⊕491838⊕1555620535,
     331361⊕863629⊕1213750126 是四个固定掩码基
```

`kH` 再把 `kM/kL/kW/kO` 解开成 4 个**语义字段** `(W1,W2,W3,W4)`（`analysis/stage2_opcodes.txt`）：

| 字段 | 不同取值数 | 分布 | 判定语义 |
|---|---|---|---|
| `W1` | **仅 182** | 全部是大整数 | **门控字**：`kH` 用 `(rotl(W1,4)⊕RE)%100 < 68` 与 `(rotl(W1,6)⊕RQ)%100 < 56` 两个概率门决定是否写入 W3/W4 槽 |
| `W2` | 3598 | `W2-W1` 通常很小（差值 top: 1→250 次, 44→136, 0→114, 48→113） | 与 W1 配对的地址/键 |
| `W3` | 909 | **53.7% 满足 \|v\|≤127，92.7% 满足 \|v\|≤65535** | **寄存器/槽位操作数**（`kH` 里先 `if RR>0x7F then RR=RR-0x80`，再算槽位键） |
| `W4` | 874 | 同上（56.1% / 92.7%） | 第二个寄存器/槽位操作数 |

> **为什么"182"是个强证据**：`W1 = (kM[i] - (Rk%256)*2 - (0x5F44⊕158443⊕0x11DDD361)) mod 2^32`，
> 而 `Rk` 是逐指令演化的滚动状态。6096 条指令只产生 **182 个不同的 W1** —— 密钥稍错就会得到 6096 个不同值。

**仍未还原的部分（如实说明）**：字符串常量的**字节已完整拿到**（例如根原型 slot 113 = `a6 3e 49 55 8d 4b`，

`RI[4]` 处理器实际调用的是 `Rl(Rj, idx-1, Rb, Ry, 0, 0)`，`Rl` = `Ry[0x37F0C56]` = `yD` 的 `RY`：

```lua
RY(v,R,k,b,y,C) = ((R%2)==0) and RK(v,R,k,b,y,C) or RB(v,R,k,b,y,C)
RK(R,k,b,y,C,X):
  Rf = ((C or 0)*0x25C5 + (X or 0)*0x552D + (k or 0)*0x757B + 0x6987824E) % 2^32
  -- 第 1 层: 逐字节 xor, 但每 64 字节块的前 8 字节跳过
  RU[i] = char( byte(R,i) ⊕ ( ((i-1)%64)<8 and (i-((i-1)%64)+64)<=#R and 0 or (Rf+i*0x67)%256 ) )
  Rd = concat(RU);  Rk = Rz(Rd, k, RA, b, y)          -- Rz 是一个 GF(2^8) 5 轮分组密码
  RX = ((RA%256) + (k or 0)*0x9F + ((b or 0)%256) + ((y or 0)%256)) % 256
  -- 第 2 层: xor + 动态 S 盒 Rj 置换 + 反馈滚动
  for Rb=1,#Rk do
     Ry = Rk[Rb] ⊕ (同样的 64/8 掩码)
     Rk[Rb] = Rj[(Ry + RX + Rb*0x35) % 256]
     RX = (RX*0xFA + Ry + 0xDF) % 256
  end
  -- 最后逆序拼接
```

`Rz`/`RQ` 依赖 `Rj`（256 项动态 S 盒，由 GF(2^8) 对数/反对数表 `f` 生成）、`RO`（`{{Rj,16,1,6},{4,8,14,13},...}` 5 轮矩阵）、
以及 `Rb/RW/RO/Rt/RH/RA/RI` 等 8 个由 `bk` 常量算出的轮键。这些我都已定位并读出，但**没有实现**（见 §5.1）。
另外 `Rb`/`Ry`（解码器的 `k`/`b` 实参）依赖被污染的运行校验和 `Rs`/`Rz`，
而 `Rs` 又依赖解码结果本身 —— 是一条必须**从 `Rs2` 起顺序前推**的链，同样需要先实现解码器。

### 4.17 `yD` 解码器的完整去混淆描述（可据此独立复现）

```

         st[i3]+=st[i4]; st[i2]^=st[i3]; st[i2]=rotl(st[i2],7)          (全部 mod 2^32)
```

**唯一的浮点陷阱**：`Rx` 里 `O(0x62,0x78,...) * j` 的乘积可达 1.17e19 > 2^53，

**采用的教训（写下来以防再犯）**：
(a) 数值字面量必须**机械地从 token 流里抽**，绝不手抄（bug 1）；
(b) 每个 C/Python 复刻都要带一个"在已证真值处复现参考实现**中间量**"的自检（bug 3、4）；
(c) 读混淆代码时，**函数头部的 `local a,b,c=…` 常量绑定行必须和函数体一起读**，

(d) **"递减循环 + 前插拼接" = 升序**。看到 `while i>0 do out = f(a[i]) .. out; i=i-1 end` 不要条件反射地当成 reverse（bug 7）；

    做变体暴力，比反复读源码快得多、也可靠得多；
(e) **要抽取 N 份同形 spec 时，先把已知的那一份重构成"通用实现 + spec"，用它自检通过后再加新 spec**（第五轮）；
    并且给每份 spec 配上"**不可能被巧合满足的离散结构约束**"（必须是 1..8 的排列 / S 盒必须是 0..255 的排列 /
    散布表必须恰好是 ≡1 mod 4 的 16 个 / 分支 A 的形参位置必须等于分支 B 的覆写下标）——
    这四条一次性验证了约 100 个手工抽取的常量，比逐字复核快得多也可靠得多；
(f) 优先找**结构性自检**（"必须是 1..8 的排列"、"必须 100% 命中 5 个键"、"必须落在 {0,1,2,3}"、
    "必须首尾不重叠单调"、"必须字节精确闭合"），它们比"看起来合理"强几个数量级（bug 6 与本轮全部验证）。

- (j) **"`vX`（`kF` 的宿主指纹，含 `collectgarbage("count")`）是常量解码的必要输入，构成一个静态不可知的 1 bit"** —— **错**。它在三处出现（`kI` 的奇偶分支、`yF` 的 `Rk` 分支、`yD` 的 `RE` 分支），**三处都是代数恒等的 decoy**（签名 60/61）。整个 Stage 2 与宿主运行时**完全无关**。

### 5.6 仍然放弃 / 未做的部分

- **88 个 handler 的语义**（§5.1bis）—— 反虚拟化的第二半，也是现在**唯一**剩下的实质性工作。
  注：第六轮已推翻我第三轮的一条推断 —— **`kH` 输出的 `W1` 不是 opcode**（它只有 182 个取值、
  且是 `kH` 概率门的输入）；真正的 opcode 是 `yL` 解出的 `f1`，它 100% 命中 438 项别名表。
  `W1` 与 `f1` 是两条不同的解码路径（`kH` 服务常量物化，`yL` 服务取指），第三轮把 `W1` 猜成 opcode 集是**错的**，现予撤回。
- **签名 36 的"opcode 滚动重映射"**：第六轮证明它是 **decoy**（`kv[Rd-RQ] ≡ kv[f1]`），已撤回"需要逐指令复现"的说法。
- **`yx` 的 88 槽 handler 名表**：第六轮查明 `yx` 填的是**反调试跳转表**（`ve[hash]=function(x) … v[Rv](x±delta+(R-RR)) end`），
  与指令 handler 表 `Rz` 是两回事；我第一轮把两者混为一谈，现予更正。
- **`kp`/`kt`/`ym`/`yL`/`kN`/`kV`/`bv`/`kD`/`kJ`/`kr` 的逐行还原**：只做了签名级识别与必要的静态求值。
- **`yo` 的 `Rj` 闭包**（`newproxy` + 弱表那套反篡改）：只用到了它的第 6 返回值 `Rx`（哈希）。
- **116 个随机字母表串的用途**：解码正确性已证，但"是混淆器生成的随机标识符还是原程序自带的密钥/盐"
  **没有独立证据** —— 这是**推断**。
- **原程序的完整逻辑重建**：我知道它调用了哪些 API（97 个标识符）、用了哪些常量（420 个 double），
  但**没有**把这些拼回控制流。

### 6.5 方法论复盘（六轮）

| 轮 | 做的事 | 结果 | 教训 |
|---|---|---|---|
| 一 | 定骨架、破 `bk`/`kg`、解载荷容器、还原 Stage 1 | ✅ 前 3 层打通 | 已知明文校准 + 揪出自己 2 个 bug |
| 二 | 找 oracle、六次穷举（2^31–2^32 × 6） | ❌ 全部为负 | **前提错了**：默认"存在未知密钥" |
| 三 | 逐条追问每个输入的来源 ⇒ 发现自由度是 0 ⇒ 定位变量遮蔽 | ✅ 字节码全解 | **先问"有没有自由度"，再问"怎么搜"**；函数头部的常量绑定行必须和函数体一起读 |
| 四 | 实现 `yD` 第 4 层解码器 | ✅ 8/25 原型明文 | 识别 decoy；**用外部结构 oracle 做变体暴力**比反复读源码快 |
| 五 | 参数化 + 抽出 `kG`/`ki`/`ku` 三份 spec | ✅ 25/25 原型明文 | **先写通用实现并用已知那份自检**，再加新 spec；**用离散结构约束（必须是排列/必须铺满/两两相加等于模数）当自检**，比逐字复核快且更可靠 |
| 六 | 找主循环、还原 `yL`、抽出 438 项别名表 | ✅ 6096/6096 指令解码并派发 | **看到 `x=a+K` 后紧跟 `t[x-K]` 先怀疑 decoy**；**当两处代码的异或键能一一对消时，角色映射可以用代数唯一确定，不必试排列**（省掉 4!=24 次尝试）；**"恰好铺满 1..88"这类离散自检能一次验证约 20 个独立转录点**；以及——**工具没写好就不要给结论**（`Rz` 切分只得 29/88，所以只认 `Rz[3]=LT` 一个，其余 87 个不猜） |

贯穿五轮最有效的一条经验：**这个混淆器的主要防御不是密码强度，而是"让人读错"**——
38 个方法用单字母变量、函数头部批量绑定语义完全不同的常量、两三层同名遮蔽、
把恒等的两条分支写成"看起来依赖运行时"（四处）、把纯异或流夹在两层相同掩码之间（掩码自相抵消）、
把升序拼接写成递减循环、四套同形解码器里把奇偶派发方向反过来两套。
**真正的密码学成分（ChaCha 式 quarter-round + S 盒 + 分块异或流）反而很弱：全是异或/加法/循环移位，没有乘法逆、没有非线性代数结构。**
所以决定成败的是"作用域纪律 + 结构性自检 oracle"，不是算力。

第六轮又补了两条同类观察：**"大魔数"往往是三层 bxor 包裹的小整数**（`yL` 的 9 个常量算出来是
`65537/17/256/257/4097/17881/2/3`，于是滚动密钥退化成一眼能读懂的形式）；
以及**"看起来在做逐指令 opcode 重映射"的机械可能整段是噪声**（`kv[Rd-RQ] ≡ kv[f1]`）。
到目前累计识别出 **5 处代数恒等的 decoy** 与 **2 处纯噪声机械**，
它们消耗的分析时间远超真正的密码部分——**这本身就是这个混淆器的主要防御成本结构**。
