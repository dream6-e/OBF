## 1. 提取结果（数字自证）

- 字节流 = **1 个 yG 组**，游标从 0 起逐字节消费到 139,714；剩余 **934 字节尾部**（96 字节高熵签名头 + ~99 组 8 字节定长记录）——装载器从不读它，判定为**完整性签名块**（同 XXSV4 的 chk 侧边数据，拆程序无关）。
- **473 个原型（proto）**，入口原型索引 **171**（`10` 条指令的 main 壳——LurAPH 典型）。
- **24,173 条指令**（每条 = 4 个 v53 变长整数，见 §3）。
- **1,963 个常量**：190 条字符串 + 609 个 i32 + 423 个 u8 + 656 个 u16 + 31 个 f32 + 4 个 f64 + 21 个 u32 + 2 个 u64 + 16 个负小整数 + 布尔若干 + 1 个 u16(tag0) —— tag 直方图全部落在模型预测区间内，**零失同步**。
- 常量是程序数据的铁证：Roblox API 字符串（`Instance/GetService/RunService/HttpService/ScreenGui/UIPadding/UDim/CFrame/Path2D/Path2DControlPoint/Random/NextUnitVector/Clone/Connect/Enums/DataModel/StarterPlayer/IsClient/IsServer/IsStudio/GetAsync/PostAsync/RequestAsync/...`）、一个 ASCII 画 logo、以及 **LurAPH loader 模板串**：
  ```
  ' --[[%s]] return setfenv(function(...) return %s(...) end, setmetatable({ ["%s"] = ... }, { __index = getfenv((...)) })) '
  ```
  （`--[[%s]]` + setfenv 环境磁化包装 = LurAPH 嵌套装载器样板；另有 VM 自身体系错误串 `'setfenv' cannot change environment...`、`The metatable is locked`、`The debug library is required on Luau platforms...`、调试切词样 `':(%d+)[:\\r\\n]'`、`'=[C]'`。）
  结论：**目标是 Roblox LuaU 脚本（GUI/exploit 面板类），内嵌一个可再装载子脚本的 loader。**

## 2. 字节流语法（全部核实，Python 复刻零失同步）

读取原语（游标共享 `y[12]`，纯顺序流，无 seek）：

| 原语 | 实现来源 | 语义 |
|---|---|---|
| u8 | hU→slot11(readu8) | 标志/tag |
| u16 | slot15(readu16) | 常量/计数 |
| u32/i32 | readu32/readi32 | 常量、ZG 池 |
| f32/f64 | aU(slot21)/zU(slot22) | 浮点常量（tag96–134=f64） |
| **varint** | VU→HU→FU，LEB128 小端组，`≥128` 续位 | 一切计数/长度 |
| **v53** | XU 偏置：varint ≥2⁵² 时 −2⁵³ | 指令流专用带符号编码 |
| u64 | 2×u32，低字在前，高字带符号修正 | tag51/52 常量 |
| 字符串 | iG：varint 长 + readstring | tag31–49 常量 |
| 字节块 | slot60：varint 长 + buffer.copy | （程序内未直接被常量引用） |

**组头**：`varint−61018 = 常量数 N`（垃圾偏移），`u8 flag`（指令存贮模式开关 j[49]）。
**常量区**：N 项，`u8 tag` + 按区间分派（0:u16, 1–11:f32, 12:true, 13–30:u8, 31–49:string, 50:i32,
51–52:u64, 53–95:u16, 96–134:f64, 135–229:−u8, 233:u32, 其余:false）。
**子项区**：`varint−41577 = 子项数 M`（本例 473）；每子项走 slot65：
1. pU：2 个 varint（第 2 个 = aux 表长 f2；第 1 个 stashed）；
2. gU：f2 个 varint —— 在字符串表 STRTAB 命中 → 取串；未中 → 拆 `{v/4, v%4}` 并注册进 STRTAB（**伪装字符串对**，供运行时合成）；
3. dU：`varint−12950 = 指令数 K`，随即 3 张 K 长配表（代码槽）；
4. uU/yU：纯建表（j[1]/j[2] 槽、槽 6/8/10 记录）；
5. **指令循环 ×K**（见 §3）；
6. ZG：`u32 计数 + 池`（偶值 → 共享表 y[j]=v/2 顺序写入；奇值 → 再读 2×u32 走区间填充）；最后 `varint → O[9]`，`-2` 收尾。

**回填**：`y[5]` 三元组 `[destTbl, destSlot, srcIdx]`，装载末段 `y5[k][y5[k+1]] = f[y5[k+2]]` —— 子原型/链接装配；`return f[varint()]` = 入口原型（本例 #171）。

## 3. 指令编码（LurAPH 的 4-varint 指令字）

每条指令 = **4 个 v53**：`v1`、`vA`、`vB`、`v4`（fU 读前三个、xU 读第四个）。
三个 3-bit 种类位：`kA=vA%8`、`kB=vB%8`、`k4=v4%8`；三个载荷：`pA=vA>>3`、`pB=vB>>3`、`p4=v4>>3`。
路由（jU 三态机 98→89→100）：`kB` 决定第一路由（4:x[a]=C / 5:−C / 6:+C / 3:bU 推回填三元组 / 1:oU 常量取数），
`k4` 决定第二路由（1:常量 / 4:直接 / 5:`a−h` / 6:`a+h` 相对地址 / 3:UU 回填）；`kA` 驱动收尾
（4:`P[K]=pA` / 6:`P[K]=K+pA` / 5:`P[K]=K−pA` = **相对跳转** / 3:eG 子原型引用 / 1:TG 或 sU 依 j49 模式存贮）。
分布：kA={2:79%,1:17.3%,3:1.9%,…}，kB={2:64.7%,6:12.9%,1:10.7%,…}，k4={2:96.8%,…} —— kind2 为直操数主模式。

已落盘的指令字段（program.json `items[].ops`）：`[v1, kA, pA, kB, pB, k4, p4]`。
`v1` 共 **161 个不同值**（top：122×5468、66×3626、55×1647、115×1591、43×766）——即 **VM 的随机化 opcode 槽值**
（LurAPH 每次保护随机置换 opcode 映射，`v1` 即本次构建的置换后派发键；对应其在 HG 中的 `x[a]=C` 形查表）。

## 4. 还差什么（最后一面墙 = HG）

- **opcode 语义**：`v1` → 具体操作（MOVE/LOADK/JMP/…）的 161→? 映射表在 **HG（21,916-token 状态机）** 内，
  由 `j[42][NN]` 数组 + 位运算网构成。拆法已定：HG 每条 `elseif o == NN` 臂 = 一个 handler，逐臂抄即可，纯体力。
- **寄存器/操作数排布**：pA/pB/p4 到 (A,B,C)/常量/跳转 的具体角色在 eG/TG/sU/BG 的存贮形式里已半明（相对跳转模式已确认），
  需随 HG 派发表一起钉死。
- 梯子上行到 **源级 CFG/伪源码**：拿到 opcode 表后可机械完成。
- 934 字节签名尾块的校验算法（若 HG 内存在运行时自校验，`error`/`pcall` 注入点是重点嫌疑——
  `_G` 阶段确实装了 `j[58]=error`、`j[61]=coroutine.yield`、',' pcall 注入）。
