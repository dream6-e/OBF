> 样本：仓库内 `XXSV4.lua` 解密所得 `luraph14.9.lua`（254,355 字节），
> 载荷为 Luraph 14.9 保护的 Roblox Luau 脚本（GUI/曲线渲染攻击类）。

## A. 词法层 —— 先杀掉解析器

### A1 非标准转义方言 ✅
字符串里混入标准 Lua 不存在的**恒等转义**：`\i \z \s \r \x \J \V \d` 等。
- 证据：`wk/tok.py` tokenizer 需求汇总（阶段报告 §2）。
- 目的：任何直接照搬标准 Lua lexer 的工具（luaparse、luacheck、luamin）立刻抛错。
- 破法：手写方言 tokenizer（42,104 tokens 全读出）。

### A2 数字字面量变体 ✅
`0b1001011_0010101_…` 带下划线的二进制字面量（Luau 方言），Lua 5.1/5.3 均拒。
- 破法：预处理替换 2 处。

### A3 全文件 = 单表构造 + 自调用 ✅
文件整体是 `({ 178 个顶层字段 }):T()(...)`，没有任何顶层语句；函数、数据、字符串混在
一个巨型匿名表里，字段顺序即唯一执行顺序（`:T()` 按序驱动 14 阶段：
`M→Q→u→G→f→v→q→j→BU→WU→AU→_G→nG`）。
- 目的：反编译器（unluac / decompiler）输出会变成一张 178 项的表字面量，逻辑全碎。
- 证据：阶段报告 §1（字段切分器 + 关键字栈）。

## B. AST 层 —— 让人读不下去

### B1 函数→表字段遍地开花 ✅
177 个非函数字段里真正的数据只有几十个，其余全部是**函数字段**；每个函数体内部又
是手工状态机（`for k=a,b,s do if k==c1 … elseif k==c2 …` / `repeat … until false`）。
单步赋值被拆进 2–4 个状态节点，控制流变成图。

### B2 槽位间接层 + 九种子位混合 ✅
所有状态跳转常量都不是字面量，而是 `R.YS(R.FS(R.SS(....)...))` 形式：
`R.w[1..9]` 九颗种子（59318 / 31969201 / 3507499010 / …）经 bit32
移位-异或-循环-三一律（`a<b and x or y`）逐位混合出来。
- 目的：静态阅读者永远看不见"下一个数是多少"。
- 弱点：**一旦符号表（`R.VS=countlz …`）被核出，即可整网求值**——本次即此法。

### B3 不透明谓词（永真/永假守卫）✅
分发树、装载器与阶段函数里遍布以 r[333]/j[37]/j[14] 等"看似活"槽位构造的
恒真/恒假分支：`y[37]==2/25/177`、`y[10]==2^31`、`j[10]==209*j[10]`——**永假**；
`j[14]~=j[50]`、`j[37]==236` 路径锁——**恒真**。真逻辑藏在假守卫里，假逻辑反过来。
- 破法：把守卫按"空格归一化 + 恒等求值"过滤（`j[37]==236`→True），真臂自动浮出。

### B4 死代码/垃圾状态 ✅
VM 指令流里插有**永不执行的指令**（例：入口 proto 第 9 号 `SETTABLE_LIT r219[r205]`
被跳转环 1→10→2 绕过）；装载器还有 1e-XX 诱饵分支。
- 破法：执行序跟踪（cflow.py），未访问即死代码。

## C. 容器层 —— 字节流加密与读取代数

### C1 定制 Ascii85 ✅
`b'LPH@…'` 前缀魔数，去掉 4 字节头后 5 字符 → 4 字节**大端 Ascii85**
（`52200625=85⁴`、`614125=85³` 数学核验），并自创 **z-run 压缩**：`'z'` 展开为 `"!!!!!"`
（本样本 956 处）。解码产物 = `stage1.bin`（140,648 字节）。
- 目的：非标准编码 → 现成的 base85 解码器全错（Python 自带 a85decode 参数不符）。

### C2 复合读取代数（带陷阱）✅
游标共享 `y[12]` 的**纯顺序流**；原语矩阵：u8/u16/u32/i32/f32/f64/u64/
LEB128 varint，以及 VM 专用 **v53（varint≥2⁵² 时 −2⁵³ 的有符号编码）**。
- 陷阱1：组头数量带垃圾偏移（常量数 = varint−61018；子项数 = −41577；
  指令数 = −12950），不还原偏移就整流错位。
- 陷阱2：穿插"伪装字符串对"：辅助表的 varint 若未命中字符串表，按 `{v//4, v%4}`
  注册进 STRTAB——供运行时拼字符串用。
- 破法：复刻读取代数，**字节流零失同步**（139,714 字节全部消费到位）作自证。

### C3 签名尾块 ❓→🟡
流结束后剩 **934 字节**（96 字节高熵头 + ~99 组 8 字节定长记录），**装载器从不读它**。
判定为完整性签名块；同 XXSV4 外层 chk 侧边数据。运行时自校验算法未解开。

## D. VM 层 —— 真正的核心墙（✅ 已被整体反汇编）

> 产物：`program.json`（473 protos / 24,173 指令 / 1,963 常量）→
> `disasm-all.txt`（语义已解 **99.94%**）。

### D1 定制寄存器 VM + 壳入口 ✅
每个 Lua 函数被编译成一张"指令表"，由 `j[64](O,a)` 闭包工厂装载；
入口原型 #171 只有 10 条指令（`args→r1..r3; r2[1]=r3; return`）——典型 Luraph 壳。

### D2 每次构建随机化的 opcode 编号 ✅
操作码槽值共 **161 个非连续整数**（122×5468、66×3626、55×1647、115×1591、43×766…），
它们在编号空间中的位置每次都随机置换——**没有"MOVE=1"这种彩蛋**。
- 目的：防"按操作码直读"的全自动工具。
- 破法：不猜编号，**从分发树手臂文本反推语义**（本报告全部 161 个已完成）。

### D3 二分比较树分发（非 jump table）✅
分发不是 `dispatch[o]()`，而是对 `local o=J[K]` 的**嵌套 if-else 二分比较树**；
真手臂被垃圾守卫（B3）包裹。
- 目的：① 防模式匹配直接抠派发表 ② 让静态符号执行必须解析整棵树。
- 破法：`tree2.py`+`armpath.py` 把二棵树一次性全展开成 guard-path → arm。

### D4 垃圾守卫包裹真臂 ✅
见 B3。真臂两侧是恒等垃圾（`v,j[47]=j[37],(-j[24])`）与死循环（`while j[37] do j[24]=56 end`）。

### D5 4-varint 指令字 + 3-bit 路由位 ✅
每条指令 = 4 个 v53（`v1,vA,vB,v4`），每个操作数带 **3-bit kind**：
`1=常量索引 · 2=寄存器/字面量 · 3=子proto引用 · 4/5/6=跳转偏移(绝对/前/后)`。
同一通道经 jU 三态机物化成多张字母数组——
`A→l[K]/h[K]`、`B→Q[K]/P[K]`、`C→k[K]/C[K]`、`J[K]=v1`。
- 目的：操作数**分裂**到 6 张表里，调试器"单步看一条指令"时拿不到完整操作数。

### D6 控制流扁平化 + K+=1 偏置 ✅
跳转类指令占 **22.6%**（5,468/24,173）。所有线性代码被切成块、用
相对跳转环串起（例：入口 1→10→2→…→8），再叠加 **K+=1 落地偏置**。
- 偏置铁证：无偏置时入口构成死环却有 RETQ，矛盾；+1 时全环自洽。见《反汇编报告》§3。
- 破法：执行序跟踪，环自然展开，死指令（B4）显形。

### D7 微操作链（指令炸裂）✅ ← 本次最漂亮的防御机制
分布局部变量 `I,Z,u,X,p` 声明在 while **之外**、跨分发存活。于是 Luraph 把
**一条高层 VM 指令炸成 2–5 条"链式微操作"**散布在流中：

```
   [29]  I=regs; Z=r2          ┐
   [48]  I=I[Z]; Z=const        │  表面上无关的挪来挪去
   [28]  u=regs                 │
   [51]  X=r3; u=u[X]           │
   [147] I[Z]=u                 ┘ ← 提交点：实际是 B[r2][key] = B[r3]
```
- 目的：静态单指令分析拿到的永远是"半句话"；动态调试器在链中间断点毫无意义。
- 破法：对 5 个链变量做**符号回放**，遇到提交类微操作（147/31/69/53/120/149/59/32）
  坍缩成一句完整赋值。

### D8 常量运行期折叠（FOLD52）✅
7 个操作码（1/14/15/18/24/63/89）的手臂本体是 `while true do if p==31 then Z*=u; …`
型**2⁵² 乘梯状态机**，常量在运行时经 bit32 网算回来（`4503599627370495=2⁵²−1` 出现在梯中）。
- 目的:常量表里没有这些数,静态翻常量表就看不到真实常量。
- 现状：机制已识别，数值未展开（反汇编保留占位符）。

### D9 上值盒对象化 ✅
上值不是寄存器位，而是 **{[1]=3, [2]=self, [3]=value} 三元组盒对象**；
读/写经 `I=a[kK]; I[2][I[1]]=hK`（o=114 等 3 个操作码）。
- 目的：反编译器按"本地上值"建模就会完全错位。

### D10 循环状态堆化 ✅
numeric-for 的状态不进寄存器，而是包进**链表节点**
`H={[5]=W, [4]=n, [2]=E, [3]=H}`（o=90 FORPREP / o=33 链下移）；
generic-for 用 **coroutine.wrap** 驱动（o=62），yield 出 `(true, k, v)`。
- 目的：循环变量在寄存器文件里根本找不到 → 数据流分析断链。

### D11 环境虚拟化 + 闭包环境磁化 ✅
VM 不用真 `_ENV`，而是用 `j[43]=getfenv` 捕获宿主环境进 `q`，
**每次创建内部闭包时 `setfenv(p, q)` 磁化**（o=137 CLOSURE）。
环境键全部哈希化（D12）。常量表内还有 Luraph 的**嵌套装载器模板**：
`' --[[%s]] return setfenv(function(...) return %s(...) end, setmetatable({["%s"]=…}, {__index=getfenv(…)})) '`
——即被保护脚本还能再装一层子脚本（Luraph 支持嵌套保护）。

### D12 标识符哈希化 ✅
方法表 / 环境表的键不是字符串，而是**单向哈希数字**
（`t[41]`、`t[62500988]`、`t[161257668]`、负值 `t[-59488]` 等），
残存的字符串标识符也已被改名（`'nnAUHOR'`、`'slnaf'`、两条 UTF-8 乱码串）。
- 目的：就算拿到反汇编，方法名语义仍不可恢复。
- 性质：**单向函数，静态不可反演**——这是本次已声明的理论边界。

### D13 伪造 debug 库 ✅
常量表带全套 debug 库成员词汇：`short_src / getinfo / what / namewhat /
currentline / lastlinedefined / linedefined / traceback / islclosure /
iscclosure / nparams / isvararg / isyieldable`。
- 目的：① 反编译/反混淆工具常用 debug.getinfo 取源码 → Luraph 给假的；
  ② 同时支持 script 用 debug API 的兼容（Luau 沙箱 executors 常缺 debug 库）。

### D14 错误重写（抹掉 VM 帧）✅
解释器尾部错误分支把所有错误消息重写为 `'Luraph Script:'…` 形式，
行号槽查不到就用 `'(internal)'`——**让抛错看起来只来自脚本本身，不漏 VM 帧信息**。

### D15 调用规约粉碎 ✅
调用/返回被拆成 15+ 个变体（CALL0/CALL1/CALL2/CALLN1/CALLX1/CALL0_0/…/RET1/
RETRANGE/RETC/RETVC），参数窗用 `table.move`(j[41]) 重组、
返回窗用 `unpack`(j[28]) 展开，还用 `e` 槽存"参数窗顶"——
目的：防止按"Luau 标准调用约定"做过程重建。

## 3. 总评（直白版）

Luraph 14.9 的真实强度不在加密（C 层 Ascii85-z 只是编码）也不在外壳（A/B 都能手撕），
而在 **VM 层的"语义去关联"组合**：
> 随机 opcode（D2）× 树分发（D3）× 操作数分裂（D5）× 扁平化+偏置（D6）×
> 微操作链（D7）× 常量折叠（D8）× 作用域去关联（D9–D11）

这七个机制两两正交、互为备份：只解其中两三个，拿到的都是"半句"或"无名表"。
本次全破靠的不是更聪明的算法，而是**为每一层配制的通用消解器**（tokenizer→
字段切分→槽位求值→流式读取代数→二分树展开→通道回归→执行序跟踪→链坍缩），
最终达成 24,159/24,173（99.94%）指令的语义恢复。

**不可恢复原项只剩两类**（诚实清单）：
1. 标识符哈希（D12）——数学上单向；
2. 运行期折叠常量的具体数值（D8）——需要"模拟执行（非执行）"一个微解释器才能
   展开，本次按用户规则（纯静态）保留占位。

## 4. 生成器视角：Luraph 把源码变成这份文件做了什么？

按证据倒推，Luraph 14.9 的保护管线（源 → 产物）大致是：

```
Lua 源码
  │ ① 编译为自有寄存器 VM 程序对象（函数→proto 树，本例 473 个）
  │ ② 指令层混淆：
  │    - 控制流扁平化（代码切块 + 相对跳转环串联，跳转占比 22.6%）
  │    - 指令炸裂成微操作链（1 条 → 2~5 条，链变量外置跨分发存活）
  │    - 死指令插入、K+=1 落地偏置
  │    - opcode 编号本构建随机置换（161 个非连续槽值）
  │ ③ 数据层混淆：
  │    - 常量池 tag 派发打包（u8 tag 按区间分派 21 种类型）
  │    - 标识符单向哈希为数字键（方法名/环境名永不还原）
  │    - 字符串切割进 aux 表为 {v//4, v%4} 伪装对，运行时再拼
  │    - 部分常数不落盘 → FOLD52 2⁵² 乘梯运行时重算
  │ ④ 序列化：varint 计数带垃圾偏移（−61018 / −41577 / −12950）
  │ ⑤ 装载器合成：
  │    - 178 字段单表外壳 + `:T()` 驱动 14 阶段状态机
  │    - 全部状态常量经 9 种子 bit32 混合网运算
  │    - 载荷 Ascii85-z 打包成 `b'LPH@…'` 字面量 + y[38] 解码器
  │ ⑥ 词法外壳：自定义恒等转义 + 0b…_ / 0X…_ 变体数字字面量（反 lexer）
```
