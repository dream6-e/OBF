# 突破报告（三）：分发树语义 → 符号执行反汇编 → 目标程序确认

本报告接续《突破报告-容器与指令流.md》。此前已完成：字节码容器解码（473 protos、
24,173 条指令、1,963 个常量）、分发二分树的 guard-path 解析（`oplist.txt`）。
本报告记录其后取得的三项决定性突破与最终成果。

---

## 1. 操作数通道路由的实证绑定（打破"代数字母"僵局）

**僵局**：指令存储为 7 元组 `[v1, kA, pA, kB, pB, k4, p4]`（操作数 + 三个 kind 位），
而处理器手臂使用字母流 `l[K]/h[K]/k[K]/Q[K]/P[K]/C[K]/J[K]`。早前试图用代数方程
反推字母→通道映射（"l=P"之类）与数据矛盾，被放弃。

**突破 × 确认路径**——对 8 个高频操作码用手臂文本和指令元组做回归：
- v1=122（5,468 条，占 22.6%）：手臂 `K = Q[K]`；其数据中 kind 位恒为 kB∈{4,5,6}。
  与 jU 路由梯 `x[a]=C / a−C / a+C` 对齐 → **相对跳转，kB=4 绝对、5 反向、6 正向**。
- v1=55 GETTABLE：`B[lK] = B[kK][PK]` ↔ (pA, p4, pB const)；
  v1=43 SETTABLE：`B[kK][hK] = B[QK]` ↔ (p4, pA const, pB)；
  v1=83 SELF、v1=115 LOADK、v1=66 MOVE 全部同构。

**结论（普适绑定表，已在全部 161 个在现 v1 上无矛盾运行）**：
```
通道 A → l[K]/h[K]（kind1 时 = 常量索引, kind3 = 子 proto 引用, kind4/5/6 = 跳转目标）
通道 B → Q[K]/P[K]（同上；122 族跳转全走此通道）
通道 C → k[K]/C[K]（kK 多为"原值/跳转"，C[K] 为 kind1 常量物化 / kind2 字面量）
J[K]   = v1 操作码本身
```
→ 所谓 kind 位就是每个操作数通道的"路由类型"：1=k 常量、2=寄存器/字面量、
3=proto 引用、4/5/6=跳转偏移（绝对/前/后）。

## 2. 链式微操作的符号执行（解决"乱序链"）

**特征发现**：分发器的局部变量 `I, Z, u, X, p` 声明在 `while` 循环**之外**——
跨分发持续存在。因此 LurAPH 把单条高层指令炸散成一串微操作流
（如入口 proto 的 `[29][48][28][51][147]`）：
```
[29] I=regs; Z=r2        # I := B（寄存器文件）
[48] I=I[Z]; Z=k[29]="1" # I := B[r2]; Z := 常量31号
[28] u=regs              # u := B
[51] X=r3; u=u[X]        # u := B[r3]
[147] I[Z]=u             # B[r2][1] = B[r3]   ← 提交点
```
→ 反汇遍器对 `I/Z/u/X/p` 做符号回放，遇到提交类微操作
（147/31/69/53/120/149/59：`I[Z]=u` / `Z[u]=I` 等）即坍缩为一条高层赋值。

## 3. 控制流环的展平与 K+=1 偏置的证明

**反证法**：解释器尾部确认分发树后执行 `K += 1` 才回到循环。
- 若偏置为 0：入口指令 1 `JMP(B通道,kB=6,pB=8)` → K=9 → 指令 9 SETTABLE →
  指令 10 `JMP@1` → K=1 → **死循环**（与 RETQ 存在矛盾）。
- 偏置 +1：1→10→2→…→8→RETQ ✓ 所有跳转环一致。

据此实现**执行序跟踪**（cflow.py）：JMP 环被展开，LurAPH 的控制流扁平化在
反汇编输出中消失，代码恢复线性顺序。

（N=pcall、i=type、iS=bxor、Z=rshift、NS=table.move、X=table.create、
P=string.match、t.wrap=coroutine.wrap…）。全表：
