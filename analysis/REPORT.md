## 2. 逐步流程（假设 → 操作 → 观察 → 结论）

### Step 1 — 摸清形态

- **假设**：单行大文件，多半是打包器而非手写混淆。
- **操作**：`wc`、`awk` 统计行长；正则统计 `getfenv/loadstring/pcall/bit32/game/task`。
- **观察**：1 行 / 148,378 字符。`getfenv` 出现 2 次，`loadstring/pcall/debug.` **0 次明文**。
- **结论**：所有敏感 API 名都是**运行期拼出来的**，不能靠 grep 找。必须先解名字。

### Step 2 — 建 AST（先踩了一个坑）

- **假设**：用 `luaparse` 解析比肉眼读靠谱。
- **操作**：`luaparse.parse(luaVersion:'5.3')`。
- **观察**：报错 `')' expected near 'b100'` → 文件里有 `0b100` / `0b10`。这是 **Luau 特有的二进制字面量**。
- **结论**：**目标平台是 Luau（Roblox），不是标准 Lua**。归一化这 2 处后解析成功，顶层结构 =
  `local w={} return setmetatable({[9088]=..., [1910]=..., ["g"]=..., [7594]=..., [901]=...}, w):g()`
  → 5 个模块，入口是 `:g()`。

### Step 3 — 打掉不透明谓词（第一个决定性突破）

- **假设**：满屏 `(cond and A) or B` 是恒等三元式。
- **操作**：正则统计形态；写常量折叠器（`w.e=256, w.aa=65536, w.ab=65521, w.h=2^32`），对 `(P and X) or Y` 求值 X、Y，**若 X==Y 则直接替换为该常量**。
- **观察**：`(3*w.e+139)` 与 `(1102-195)` 都等于 **907**。一次跑掉 **829 个三元式 + 2,809 次算术折叠 + 871 个恒真/恒假谓词**。
- **结论**：`(P and X) or Y` 里的 P 是**纯噪音**，所有跳转目标都是编译期常量。状态机可以静态还原。

### Step 4 — 解名字表（第二个决定性突破）

- **假设**：`[1910]` 模块里 30 个 `function() return "q" end` 是字符表。
- **操作**：提取 30 个单字符 → 字母表 `qutz6kwgychml21snboed3xr4pa8fi`；把所有 `x(j,{16,20,13,20,10,3})` 形态按下标映射回字符串。
- **观察**：41 处全部解出 —— `select`、`error`、`pcall`、`string.byte`、`bit32.bxor`、`buffer.create`、`buffer.readu8`、`debug.info`、`loadstring` …
- **结论**：确认 **Luau**（`buffer`、`bit32` 库）。我把 51 个返回值按位置对齐到外层 51 个局部名，做了**作用域感知重命名**（647 处），代码瞬间可读。关键收获：**`k()` = `error`** → 所有 `k()` 都是"校验失败自毁"点。

### Step 5 — Base-86 解码器

- **假设**：`j[66]="!4fdWU BX^V…"`（恰好 86 字符）+ `j[87]={13 个长串}` 是编码载荷。
- **操作**：读 `t[8255]/[7919]/[5850]` 三个函数的状态机，实现其算法。
- **观察**：算法 = 变长 base-86；分块首字符是**乱序索引**（`(map[c[0]]-shift)%86` 给出真实块号）；主体按 `prev%3` 选择 4/5/6 位 → 3/4 字节。
- **关键陷阱**：`[7919]`、`[5850]` 解码失败（`eof`）。原因是它们的字母表数值有一个 **`shift`**，而 shift 由**上一阶段的明文**算出：`shift = ((Σ(byte)*256) + len) % 86`。
- **结论**：三段是**链式**的，必须按 8255 → 7919 → 5850 顺序解。得到 **17,740 字节，magic `XXS:`**。

### Step 6 — ChaCha8 与密钥（第三个决定性突破）

- **假设**：`t[615]` 里的 `{1634760805, 857760878, 2036477234, 1797285236}` 是 ChaCha 常量。
- **操作**：`struct.pack('<I')` 还原这 4 个数。
- **观察**：得到 ASCII **`"expand 32-byte k"`**。`t[3572]` 是标准 QuarterRound（`+`,`^`,rot 16/12/8/7），`t[615]` 跑 **4 轮双轮 = ChaCha8**。
- **密钥来源**（全部可静态计算）：
  - `mp/le/qt`：Lehmer LCG（`16807 mod 2^31-1`），种子是**字面量对** + `debug.info(loadstring,"s")`（对 C 函数恒为 `"[C]"`）+ 常量串 `"buffer|bit32|table|freeze|debug|info"`。
  - `ii`：从硬编码串 `"\127?VS@q<"` 解出 → **158665**。
  - `IS`：`t[7015]` 的"反调试指纹"，输入恒为 `"[C]"`，输出恒为 **2392745008**。
- **结论**：所谓"环境指纹"**完全不依赖真实运行环境**，是可静态求值的常量。这是这个保护方案最大的设计缺陷。
  算出 `mp=678919948, le=809326533, qt=1052881061, ii=158665`。

### Step 7 — 验证解密（自证正确性）

- **操作**：实现 `t[2902]`（ChaCha8 keystream ⊕ 明文 ⊕ **前一个密文字节**，即密文反馈链），再跑 `t[5189]` 的全部头部校验。
- **观察**：
  ```
  magic n     = 2652246018  == 期望 2652246018   MATCH
  payload len = 17718,  16+t+pad == 17736 == 实际  MATCH
  校验和 o    = 2864739368  == 期望             MATCH
  双 Adler mp = 3360617640  == 期望             MATCH
  padding[1..2] = 206, 223  == 期望             OK
  ```
- **结论**：**4 个独立校验 + 2 字节 padding 全中**。这不是"看起来对"，是**密码学意义上的确定性正确**。

### Step 8 — LZW

- **观察**：载荷头 magic = `22501964` = ASCII **`"LZW\x01"`**。头部给出 `uncompressed=18038, bits=141610, adler=3277475975`。
- **操作**：第二层 ChaCha（`t=2` 变体，nonce 种子 `uh` 由长度派生）解出比特流，再实现其自定义 LZW：8192 字节分块重置字典；3 种码：`1`→8bit 字面量（且必须 ≥32）、`01`→5bit、`00`→变长 `256+read(ceil(log2(i-256)))`。
- **观察**：解压得 18,038 字节，**Adler-32 = 3277475975，与头部声明完全一致**。
- **结论**：✔ 正确。尾部 6 个 slack bit 为 0 的校验也通过。

### Step 9 — `OBF\x02` 容器

- **观察**：magic `OBF`, ver 2, `'u'`(117), `[1,1,0]`, headerlen 32, 18 个原型, 常量 19, Adler `0xb8944c4f`（自校验通过）。
- **操作**：按 `t[7240]` 的解析逻辑实现原型头、upvalue 描述符表、碎片表。
- **关键陷阱**：碎片表不是"表在前、数据在后"，而是 **三元组与数据交错**。且每个三元组被 3-元素置换 + 模加掩码（`perm3(k, addend)`）打乱。
- **观察**：
  - 18 个 `chain` 字段全部解出 `(chain - i*53011 - 34510) % 65536 == i*2+1` ✔ 18/18
  - 36 个碎片按链表 `j → w[2]` 两跳重组，**每个原型长度精确匹配声明值**，`pos == 18038`（一字节不剩）。
- **结论**：容器结构 100% 还原。

### Step 10 — 常量池

- **操作**：实现 `ia()` 的 TLV 解析（tag 0/1/2/3/4/5 → nil/bool/double/string/int64/longstring）+ `cl()` 滚动密码（`j=(key+119)%256; v=(c-j)%256; j=(j*193+v*109+217)%256`），密钥 `i` 随每个常量演进（`i=(i+t*257+54108) mod 2^32`）。
- **观察**：**68 个常量全部解出，无一乱码**（见 §4）。
- **结论**：✔ 完全还原。

### 3.2 不透明谓词签名（打掉它们是第一个突破口）

抓到 7 类恒等谓词，共 **~700 处**：

```
(x ~= x-1)        → true      109 处
(not (x < x))     → true       92 处
(x <= x)          → true      101 处
(x * 0 == 0)      → true       95 处
(x - x == 0)      → true       91 处
((x // 1) == x)   → true       92 处
(x-i == x-i)      → true      117 处
(t+C) - C == t    → true       (变体)
(j<=j and j or 0) ~= j → false (嵌套变体)
```

配套的**双臂等值三元式**：`((P) and (3*w.e+139)) or (1102-195)` —— 两臂都 = 907。
**判据**：不看 P，只对两臂做常量折叠，**相等就直接替换**。829 处一次清空。

### 4.6 VM 指令格式（已还原编码，语义部分还原）

每个原型体布局（已验证 18/18）：
```
[0:2]        u16  基本块模板数量 n (1..512)
[2:g]             块模板表 + 基本块数据
[g:len-4]         常量池（TLV + 滚动流密码）
[len-4:len]  u32  常量池长度
```

**块模板表**项格式：
```
u16 id ; u8 q(1..4) ; 重复 q 次 { u8 d ; u8 i }
opcode = (d - (id*37 + (k*2)*47 + 15) % 256) % 256      -- 0..255
rot    = (i - (id*37 + (k*2+1)*47 + 15) % 8) % 8        -- 必须 <= 4
```
已成功解出所有原型的模板（示例 proto 0）：
```
tmpl id=15488 len=1 ops=[(234,2)]
tmpl id=41827 len=4 ops=[(45,1),(234,2),(243,1),(234,2)]
tmpl id=49524 len=3 ops=[(78,2),(72,2),(228,3)]
tmpl id=64348 len=4 ops=[(228,3),(72,2),(218,2),(254,4)]
```

**基本块**：每块读 4 个 u16 `(b,u,di,pk)`，经 4 元置换 `p[]`（由 `(x*11+4)%24` 派生）还原为 `(t,s,g,p)`：
- `t` = 块 ID（非 0、不重复）
- `o = o(p, t, cx, is, x)` → 模板 ID（`d()`/`o()` 是两个 ~10 轮的乘加混淆函数，已完整复刻）
- 每条指令的 3 字节操作数按 4 种布局之一（`a=(x*1+2)%4`）打散到 `k[6+d*13 ...]` 槽位

**CFG 终结符语义**（来自块图校验，F17）：
| opcode | 含义 |
|---|---|
| 149 | 尾块 / 间接跳转（要求 `i[j[19]]` 存在，`q==k==0`） |

### 4.7 各层算法（完整伪码，可复现）

```python
# L1 base-86（链式）
shift = 0 if first else ((Σ(prev_plain[i])*256 ... ) + len(prev_plain)) % 86
digit[alpha[i]] = (i + shift) % 86
块重排: idx = pos_in_alpha(chunk[0]) % 86          # 1..nchunks，不可重复
主体: num = Σ digit[c]*86^k ;  prev%3 → (4,3B) / (5,4B) / (6,4B)
尾部: rem==4 → (5 或 6 位, 4B) ; 3→(4位,3B) ; 2→(3位,2B) ; 1→(2位,1B)

# L2 ChaCha8 + 密文反馈
h[0..7], nonce[0..2], ctr 由 (mp, le, qt, ii, len, variant, IS) 线性组合
j = ChaCha8(h, ctr, nonce) ; h=j[0:8] ; n=j[8:11] ; ctr=(j[11]+variant+ctr)
每 64 字节: ks = ChaCha8(h, blk+ctr, n)
  plain[i] = cipher[i] XOR ks_byte[i] XOR cipher[i-1]      # z = 前一个密文字节

# L3 LZW（8192 分块）
'1'  + 8bit  → 字面量（必须 ≥32）
'01' + 5bit  → 小字面量
'00' + nbit  → 词典码，n = ceil(log2(i-256))，i 为当前词典大小
每 8192 字节输出重置词典

# L5 常量池滚动密码
j = (key + 119) % 256
for t in 1..len:  v = (cipher[t] - j) % 256 ; j = (j*193 + v*109 + 217) % 256
key 随常量递进: key = (key + len*257 + 54108) mod 2^32
TLV tag: 0=nil 1=bool 2=double(f64le) 3=string(u32 len) 4=int64 5=string(u32 len)
```

## 5. 卡在哪 / 没做到的

**诚实清单**：

1. **没有还原出逐行 Lua 源码。**
   我停在"VM 字节码容器 + 完整常量表 + CFG 结构"这一层。要出源码还需要再做两步：
   (a) 把 `t[7594]` 里那张**微操作表**（`{1..12, args…}`）逐条对应到宿主语义（`GETGLOBAL/CALL/ADD/JMPIF/...`）；
   (b) 写反编译器把基本块图 + 操作数还原成表达式树。
   这两步是纯工作量，但我没在本轮完成。

2. **256 个 opcode 的语义只还原了终结符那 4 个（149/98/43/65）。**
   其余 opcode 我拿到的是**编码**（能稳定解出 `(opcode, rot)` 对），但没有逐一确定语义。
   挡路的原因：opcode → 语义的映射藏在 `t[7594]` 那条 ~300 分支的 `elseif` 链里，且每个分支只做**操作数验证**（`f(n[K], {...})`），真正的执行体在微操作表里**再间接一层**。要吃透得把 `n[1..33]` 这 33 个验证器和 12 个微操作逐个对齐。

3. **`d()` / `o()` 两个混淆函数我是"复刻"而非"化简"。**
   我按状态机原样实现了它们（约 10 轮 `(x - (线性组合)) * 常数 mod 65536`），验证正确；但没求出闭式逆。不影响结果，只是不够优雅。

4. **没有动态验证。**
   全程没跑过任何 Lua。我的正确性依据是**目标自己的校验器**（2 个 Adler-32、4 个头部校验、padding、CFG 一致性、18/18 chain、pos 精确等于文件长度）。这比"能跑起来"更强，但确实没有端到端执行证据。

5. **`z=0`、`c19=19` 两个头部字段语义不明。**
   `19` 被硬编码校验（`(19 - j[6]) ~= 0 → error`），像版本/特性号；`z` 恒 0，可能是保留位。

6. **`t[9088]` 模块（userdata `:add()` 代理）我只读懂了形态，没确定它服务于哪条 VM 指令。**
   它把 userdata 的 `add` 方法包装成闭包——结合常量表里两个 `'add'`，推测和 `Vector3`/自定义 userdata 的算术测试有关，但这是**推测**。

### 一句话总结

这个保护方案的层数很足（5 层 + ~700 个不透明谓词 + 7 类反调试），但它有一个**致命的结构性缺陷**：
**所有"环境指纹"在静态下都是常数**（`debug.info(C函数,"s")` 恒为 `"[C]"`，库行为自测恒真），
导致整条密钥派生链 `mp/le/qt/ii/IS` **完全可以离线重算**。
一旦这条链被攻破，后面的 ChaCha8、LZW、容器解析全部退化为纯格式解析——
而且它**自带的完整性校验（2 个 Adler-32 + 4 个头部校验）反过来成了攻击者的免费正确性预言机**，让我能在不执行任何代码的前提下证明每一层都解对了。
