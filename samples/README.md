### 目标四：常量加密改进（2026-10-03）

- 常量节把真实常量和 1–8 个有效 f64 诱饵统一随机洗牌；不可达尾部 ADD 指令引用诱饵槽，引用折叠、滚动链、加密与整原型聚合 MAC 均包含这些记录。
- 运行时路径态以 PC 势函数推进，并混入当前实际分派的 opcode 与操作数；分支到达同一 PC 时归一到同一状态。常量解码将此态和逐槽访问计数混入字节掩码。
- 字符串走惰性 `__index` 解码，不写入明文缓存；每次读取重新解密，并按当前路径态/访问计数使用不同掩码。数值也使用同一解码路径态机制。
- 全局名作为普通字符串常量加密，GET/SETGLOBAL、GETGLOBALSTR/SETGLOBALSTR 与 GETIMPORT 每次按当前 VM 环境表解析；数值层级的 `getfenv`/`setfenv` 代理会读取或更新当前 VM 帧环境，函数目标仍委托宿主原生函数。独立 boot 名表和第五解码簇已移除。
- 验证：`test/DynamicGlobalEnv.lua` 覆盖顶层与闭包环境重绑定；普通与 MB 产物在 Lua 5.1、Luau 下均与源逐字节一致。`cargo test --all-targets` 90/90；Debug、Release、Workspace 构建通过；普通/MB 样本双运行时输出一致，三件套均通过两种语法检查；Comptesting 与 4 次随机 print 产物也通过双运行时检查。

**运行期状态链绑定**（见 `项目交接总结.md` 改进项六）：每条 handler 按解码后的 opcode 与三个操作数推进累加器，下一轮先校验影子状态，并将累加器派生偏移共同加入 opcode 和 BST 枢轴；删去状态推进会在后续指令分发前触发静默失败。

产物现在是 Luraph 风格（见 `项目交接总结.md` §5.9）：单层 `while true do` 驱动、
每个指令块是一个随机名方法、调用点全是 `self:随机名(...)`、状态存在 `self[随机大整数]`
槽位里、分发树按随机大整数状态号路由；不含任何二进制字面量。
池解码器、毒表守卫（§5.11）已做逻辑/数据流打乱；脚本头那段原生 `loadstring` 探测里
9 个字符串（`getinfo`/`what`/`source`/`getgenv`/`getrenv`/`loadstring`/`load`/`C`/`=[C]`）已 XOR 加密，
产物里不出现明文。
冷块指令处理器的调用形态已打散：方法签名（首参名 + 四个指令参数名与顺序）逐块随机，
调用点六形随机（冒号 / 点调用 / 先取函数再直调），产物里不再有清一色的 `xx:xx(a,b,c,d)`
可 grep 结构（详见 `项目交接总结.md` 末节）；
**加载器去标识符**（§5.21）：产物里不再出现 `loadstring` / `load` 这两个词，也没有
「`A or B` 取加载器」这种一眼可 grep 的算子对。两个名字登记进统一流以**数字密文**
落盘，运行期才解回字符串，再从环境表（`(getfenv and getfenv() or _ENV or _G)`，
与产物他处同一式）按名字取用：探测候选表、载荷解码入口（填充工厂）、MB 兜底外壳
三处统一改造，调用点只剩一个随机局部名。实测四种宿主形态（两式都在 / 只有
`load` / 只有 `loadstring` / 只有 Lua 包装的 `loadstring` 而原生实现藏在
`getrenv()` 里）产物均照常解出并运行。
**外壳行号自检**（§5.22，失败路径由目标六更新）：MB 自解压外壳检查自身行号——
成品压成一行，探针函数正常落在第 1 行；`pcall` 的错误消息中最后一处冒号数字用于判断
顶插或拆行，宿主不提供行号时 fail-open。目标六将行偏移从固定的 `G.error()` 早退改为
延迟状态：行号异常记入 `L`，解包完成后给解出的 VM 源码前置换行，再由内层随机守卫决定
是否、何时污染运行状态。Base85/LZ 数据结构损坏仍由解码器的结构性检查处理。
**单根密钥派生**（§5.20）：四组常量簇各自不再携带独立密钥材料；产物只留**一份**根 K0
（同样以 X/掩码 + 槽位洗牌落盘，装完即把运输表销毁），每组材料由 `KDF(K0, 组号)`
在运行期现算：密钥字用根的第 w 个字、字序号 w，盐/两个 kind 用根前三个字配字序号
9/10/11。KDF 是纯算术（32 位异或走 P 表实现 + 两次算术旋转 + 16 位拆乘归约），
读写两侧同一规格；根 K0 本身取自**原生流**（另起一条种子独立的实例，取 32 字节
密钥流折成 8 个 32 位字），产物里没有可直接对齐的「一组 8 个密钥字」。目标四实施后，
全局变量名作为普通字符串常量走同一分组加密管线；独立 boot 名表和第五解码簇已移除。
**明码字节表清零**（§5.19）：运行期指纹、守卫探针、载荷解码器与 MB 外壳里原先以
`string.char(…数字…)` / `Z(108,111,97,…)` 出现的字节表全部改掉 —— 指纹不再落任何字符串
常量（类型名走 `type(tostring(0X0))`，`collectgarbage` 的选项名在运行期从宿主串里按位取字符
拼出，第三路直接用宿主原生报错文本）；解码器的密钥分片/字母表/数字映射表整体并进统一流
（落盘只有密文数字，取用点是惰性解密表达式）；MB 外壳的 loader 名从运行期字母表里逐字符取用
拼出（产物里既没有 `loadstring` 这个词，也没有那串明码数字）；块内库成员调用点超过两次的
统一 local 化（声明散在块首、顺序洗牌），取用点只出现随机局部名。产物里 `string.char` 只剩
「表达式 → 字节」的既有用法（解码器逐字节还原），不再有可直接读出内容的数字列表。
载荷解密链与统一流（UniStream）已换代成**原生流**（§5.17）：16 字节种子不再当密钥用，
而是运行期折叠后**现场构造 S-box**（Fisher-Yates，构造路径由运行期指纹选路），
密钥流 = 双 LCG 状态 + 位置 + **前一密文字节** 混合后查该 S-box ——
滚动 16 字节 XOR 的固定周期没有了，同一明文字符在不同串、不同位置密文全不同；
密钥流内核被拆成 10 个单步碎片方法，由「随机键程序表 + 派发键表」间接驱动，
产物里既没有可读的循环体，也没有 S-box 数据（S-box 只在运行期存在）。
统一流的密文只以数字出现（零字符串字面量），解码器整段落在 `do … end` 里、
块外只暴露一个名字。十六进制数字一律写成 `0X` 前缀 + 大写 A-F；ChaCha 的 4 个 sigma 常量不再以字面量出现，
改成逐产物由随机 key 派生；**ChaCha 密钥**也换代了（§5.18）：sigma 还原式不再引用密钥表
（改成运行期随机加数取模，静态看不出密钥参与），8 个密钥字不以任何数值形态落盘 ——
真值藏在「取模别名函数 + 随机数对表」里按槽位现算，密钥装配走元表 token 运输
（中间值只在调用栈上存在），装完立即把运输表销毁；载荷解码链（bxor/rotr/read_dec/u32/字符串/状态机）已整体换形（§5.13），
解码器外层（m_main/m_init_map）也已打乱并可反美化（行号校验守卫，§5.14）——产物被拆行格式化后会失效。
MB 模式改用了新的自解压外壳（DP/LZ + base85，§5.15）：同一输入下比上一代管线小 9%、
启动（解压 + 加载）快 31%。
探测串与守卫池改用「位置相关」的两字节密钥混合（§5.16）：单字节 XOR 可以拿两次调用
比对反推密钥，现在同一明文字符在不同位置、不同串上的密文都不同；行号守卫里的字符串
（`getinfo`/`linedefined`/`currentline`/模式串/类型名）全部走池，产物里没有明文。

自己复现：

```bash
cargo run --release -- test/print.lua                    # 生成 obfuscated.lua
cargo run --release -- test/print.lua MB                 # 生成 MB 模式产物
cargo run --release -- '#U4f2a#U88c5.lua'                # 生成“伪装.lua”产物
```

第三项是 **Roblox 专用**脚本（用到 `hookfunction` / `isfunctionhooked` / `game` 等
执行器全局），在标准 Lua 下跑不起来 —— 原文件在 `hookfunction` 处报
`attempt to call global 'hookfunction' (a nil value)`，产物在 VM 启动阶段就报
`attempt to call field '?' (a nil value)`（产物运行前要先建 VM，这一步依赖 Roblox 环境），
改版前后行为一致。这边只做了能做的检查：

- 混淆器能正常编译它；
- 产物过 `toolchains/bin/lua5.1` 语法检查与 `luau-compile --binary` 语法检查；
- 产物里不含明文字段名（`项目交接总结.md` §5.8），也不含 `U4f2a` / `Instance` /
  `WaitForChild` 这类原始脚本里的明文标识符。

**实际功能由用户自己在 Roblox 里验证。**

注意产物**不可逐字节复现**：每次运行的种子（`VmContext::seed`、指令布局种子、
常量池 ChaCha 密钥、方法/状态名、分发树形状）都是随机取的，所以每次生成的字节都不同，
但行为一致。

### 目标五：ChaCha 多块字符串掩码反馈修复（2026-10-04）

- **根因**：`build_decstr` 先对 ChaCha 密文逐字节套 path/count/slot XOR 掩码，再做链式解密，最后统一撤销掩码。ChaCha 的下一块 counter 以当前 64 字节块解出的前 8 个明文字节为反馈；旧逻辑把这 8 字节也掩码了，导致第二块起使用错误 counter。第一块经过最终撤销后看似正常，长度不变，但 URL 第 64 字节之后内容损坏，`game:HttpGet` 因而收到另一个 URL 并可能返回 404。
- **修复**：只在存在后续块时保留当前块前 8 个反馈字节原样；末块仍完整掩码。其余字节仍由相同运行期种子掩码，完整解密后使用同一公式撤销。数字常量仅解一块，不受多块反馈影响。
- **回归夹具**：新增 `test/string_encryption.lua`，包括根目录伪装脚本的两条 URL、70/77/136 字节长 URL（含 `%`、`?`、`&`、`=`）、63/64/65/127/128/129 字节边界串、包含 00–FF 全部字节的 256 字节常量，以及代表性数字常量。mock `game:HttpGet` 捕获并核对实际传入 URL，输出同时含原文与十六进制字节序列。
- **验证**：普通与 MB 各 4 次独立生成；每个产物均通过 Lua 5.1 与 Luau 语法检查，并在两个运行时与源文件输出逐字节一致（4,565 B）。这直接验证源 URL、长字符串、任意字节和数值常量，而不只是 `print.lua` 冒烟。另直接调用旧 MB `pack_lua_stub_v1`（LZ + XOR + base122）包装含长 URL 的脚本，Lua 5.1 / Luau 双运行时输出也与源一致。全量 Rust 测试 **90/90**，Release 构建及 workspace 构建通过。
- **最终样本（目标六之后重新生成）**：普通 **212,496 B**、MB **96,028 B**、伪装 **271,862 B**；普通/MB 样本通过 Lua 5.1、Luau 双运行时与源输出比对，三份均通过两种语法检查。伪装脚本使用 Roblox 执行器 API，仍无法在本地验证其真实 Roblox 网络请求；`HttpGet` 字节保持一致已由回归夹具验证，远端资源是否仍有效需在 Roblox 中确认。嵌套 proto 固定样本的尺寸与专项回归见本文件顶部。

### 目标六：反篡改失败路径去固定化（2026-10-04）

- VM 守卫不再在探针命中处早退或爆栈；只设置共享投毒状态，经过约 32–96 个分发步骤后才逐步影响路由、密钥与常量。键流和字符串扰动还会按运行期对象地址抽样，结果与时机不再固定。
- MB 外壳保留行号探针，但异常不再在外壳处调用 `G.error()`；解包后通过载荷前缀换行把异常交给内层 VM 守卫。损坏 Base85/LZ 结构的解码器检查仍保留。
- 运行时抖动来自对象地址哈希，不读取或消费应用的 `math.random` 状态。
- 验证：普通/MB `print.lua` 样本在 Lua 5.1、Luau 下与源 stdout 一致；伪装样本通过两种语法检查。前置注释的篡改复测中，MB 样本两种运行时均出现不同输出长度及混合的正常返回/下游自然错误，不再在外壳探针处固定空输出退出；`cargo test --locked --offline` 90/90，Release 构建通过。

### 序列化格式（《项目交接总结》目标五，2026-10-04）

- 子 proto 写入时不再附带长度前缀、边界标记或可跳过填充；读侧按序递归完整解析子树来定位下一个兄弟 proto。字符串等实际需要的长度字段保留。
- 行号、局部变量名、upvalue 名等调试信息只从源序列化流读取并丢弃；原 name 槽改存 4 字节原型常量汇总校验值，运行时抽样核验，不再留三段可跳过的调试尾区。
- 回归夹具 `test/nested_protos.lua`（含嵌套闭包）生成普通/MB 各 20 份独立随机产物，每份分别在 Lua 5.1 和 Luau 下执行并与源码 stdout 比对：80/80 通过。`samples/nested_protos.obfuscated.lua` 与 `.MB.lua` 两个收录样本又分别在两个运行时各重复 100 次，零失败、零错输出；固定输出为 `12 6 15 12 19`、`47`。
- 全量 `cargo test --locked --offline` 为 90/90；干净 Release 构建、两种 Lua 语法检查均通过。
- 说明：此前交接记录中输出错误值 `17` 的那份具体随机文件未能在当前仓库或临时目录中找到，无法对该文件本身复验，也未据此声称已确定其根因。本轮批量独立生成覆盖了不同随机布局，未再复现。

### 目标七：非字节码/常量池路径的弱加密替换（2026-10-05）

- Native Stream、UniStream、字符串流（含 AntiTamper 池）、整段 payload 白化/滚动层，以及旧 MB packer XOR 回退均改为项目自定义的耦合状态变换；旧 fallback 仍保留 base122 编码与压缩流程。
- bytecode 序列化与常量池 ChaCha 算法未改；Native root 仍走兼容的旧 root 派生路径。压缩、base85/base122 只承担压缩/编码，不视为加密。
- 验证：全量 `cargo test` **101/101**；Release 构建通过。`string_encryption` 普通与 MB 样本均通过 Lua 5.1 / Luau 语法检查，且两运行时的输出都与源输出逐字节一致（4,565 B）；另以 Lua 5.1 对普通和 MB 各做 3 次独立随机生成回归。更新后的 `print` 普通/MB 样本在 Lua 5.1、Luau 下均与源输出一致；伪装样本通过两种语法检查且不含 `U4f2a` / `Instance` / `WaitForChild` 明文。新增的旧 fallback stub 端到端 Lua 5.1 测试通过。
- 目标七当时的固定样本：普通/MB `print` **210,665 / 100,596 B**，普通 `string_encryption` **223,062 B**、MB **109,499 B**，伪装 **273,241 B**；当前样本尺寸见本文件顶部表格及目标九。
- 这些自创变换用于提高静态分析成本，不是经密码学审计的标准密码算法；不对其作标准密码学安全性声明。

### 目标八：自定义 VM ISA 与 Lua 5.1 差分回归（进行中，2026-10-05）

### 第 ⓪ 步：源码最小化（2026-10-06）

- 进入编译器前先做**词法级**源码最小化（`src/minifier/`）：去注释 + 最少空白 + 单行化，**非 LZ、不改语法树**。
- 只删注释与可忽略空白 ⇒ 令牌序列不变、语义不变；自带「重新分词自检」，任何拿不准的输入原样放行；
  不依赖文法，因此覆盖全部 Lua 5.1 与 Luau 词法（含 `print "x"`、Luau 插值串/类型标注/`+=`/`//`/`->`）。
- 编译失败会自动回退原始源码；`--rob` 的 `Check.lua` 不参与最小化。
- **体积口径（A/B 实测）**：源码侧变小（print 557→441 B、nested 817→399 B、roblox 14,580→6,657 B），
  但**产物体积在噪声内不变**（nested 普通 +0.06%、nested MB −0.29%、roblox 普通 +0.21%，符号不一致）。
  原因：字节码不含局部名/空白/行号，载荷只受指令数与字符串常量池影响。
- 原计划的「重命名器压源码」已实测**不可用**（会改名全局/成员，破坏 Roblox API 与字符串键；且对载荷 0 收益），未采用。
- 本次普通/MB `print` 样本为 **214,684 / 102,239 B**，伪装样本为 **321,910 B**。

### 源码字符串加密（第 ⓪′ 步，2026-10-06）

- 编译成字节码之前，源码里每个字符串字面量都换成 `解密函数("密文")`：
  `local msg = "Hello"` → `local msg = YJL("_)O,w]g{y?]o")`。运行期用注入的纯算术解密壳解回原值。
- **算法（2026-10-06 强度升级）**：两条随机 LCG 进位耦合出密钥字节（`((s1+256*s2) mod 2^32) >> 24`），
  再经逐产物随机的**模 257 乘法替换** `x ↦ (x+1)*M mod 257 - 1`（257 为素数 ⇒ 双射）；
  每字面量 8 字节随机种子。全程只用 `%`、`/`、`math.floor`、`string.byte/char`、`table.concat`，
  不依赖 bit/bit32（Luau 无 bit 库）。
- 强度定位：**混淆级**（不是密码学）。相比此前的单流加法，逆向者不再能靠"一对明密文解个方程"批量还原，
  需要同时重建两条流的状态与替换常数。
- 自动生效，无需任何命令行开关；`--rob` 的 `samples/Check.lua` 检测脚手架按既有约定不参与本步骤（也不参与最小化）。
- 本次普通/MB `print` 样本为 **238,941 / 127,042 B**，伪装样本为 **409,769 B**；
  三份均过 `luac5.1 -p` 与 `luau-compile`，普通/MB 两件在 `lua5.1`、`luau` 下与源 stdout 逐字节一致（各连测 3 次）。
- 体积代价：注入壳约 **+23 KB / 产物**（固定），另有每个字面量约 +0.5 KB；解密耗时约为上一版的
  **1.2–1.5 倍**（逐字面量、首次使用时一次）。详见 `项目交接总结.md` 末节。

### 目标十：顶层前置声明移入 `return({})` 壳（2026-10-06）

- 动机（用户指示）：产物开头的 `local K=... local Y=false; local G=type; local a=pairs;` 中，**除 `...` 捕获外全部移入 `return({})` 壳内**，顶层只留主 chunk 的 vararg 捕获。
- 实现（`src/VM/VM_Backend/Generator_chain_tail.rs`，纯改生成顺序，不动 VM 语义）：
  - 顶层只发一条 `local <var_l> = ...;`（主 chunk vararg，供壳内 `execute` 第 6 参使用），紧接开壳 `return ({ <wai>=function(...)`；投毒旗 / `type` / `pairs` 三条声明改在 `wai` 函数体开头发出（其后才是原有的沙箱与 select 桩）。
  - `fu`（壳尾表字段）改为**自带一份 `local <native_type>=type`**：它原本依赖顶层 `type` 局部，现在与 `wai` 是壳内兄弟字段，共享不了词法作用域；实测 `fu` 只用到 `type`（2 处），不涉及投毒旗与 `pairs`。
  - 物理行结构不变（压缩前 3 行、压缩后 2 行），`⑳ MB` 的「解压后 VM 逻辑为第 2 行」行守卫假设不受影响。
- 效果：成品开头由 `local K=...local Y=false;...return({...` 变为 `local K=...return({...`，`type`/`pairs`/投毒旗在顶层不再有任何痕迹。
- 验证：`cargo test --offline --all-targets` **143/143**；语法门（`luac5.1 -p` + `luau-compile`，含真 MB 模式）**52/52**、回退 0（`test/Katchi.lua` 两模式均为既有生成失败：Luau 端 `function or expression too complex`）；本改动前后二进制 A/B（普通 50 项 + MB 7 夹具）除既有偶发外行为一致（`Prometheus/metatables.lua` 普通 旧 4/60 vs 新 2/60；`test/roblox.lua` MB 旧 2/15 vs 新 1/15，均属已知「MB/随机产物偶发损坏」）。
- 本次普通/MB `print` 样本为 **245,816 / 124,325 B**，伪装样本 **362,845 B**；三份均过两种语法检查，普通/MB 两件在 `lua5.1`、`luau` 下与源 stdout 逐字节一致（各连测 3 次）。尺寸与上一版同水平（随机种子抖动 ±3%），本改动**不以省体积为目的**。
- 边界：产物外层仍保留 21 B 明文头与自解压/解密壳，本改动只是让**顶层**不再出现工具声明；「一个明文字符都没有」仍不可能，运行性以用户在 Roblox 实测为准。
