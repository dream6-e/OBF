## 工具

```
tools/an.py         结构解析（handler 切分 / 别名表 / 块配对）→ 生成 handlers.json 等证据文件
tools/pretty.py     按 token 栈重新缩进任意 handler，便于阅读（只插空白，不改文本）
tools/ops.py        dispatch 树重建（对判别变量做区间传播，else 取补）→ opcode 语义
tools/lph_codec.py  容器解码（pC 转义 → radix-85 → u32 字流）+ 均匀性自检
tools/audit.py      静态泄漏自检（把分析者用的锚点做成 build 时断言；对本样本跑出 71 项 FAIL）
```

## 结论边界（诚实声明）

**已还原**：容器编码链（radix-85 / 读窗 / 位权，含可证伪的统计自检）、完整 import 表（68 槽 + 14 名）、
VM 架构（SoA 帧、4 棵 dispatch 树、自改写与 `pc-=1`）、常量加密方程（尺寸分桶 + LCG 密钥流 + 盐值）、
opaque 算术恒等式及其折叠、入口控制流、约 40 条指令的逐字语义、45 项混淆技术。

**未还原**：原始 Lua 源码、常量与字符串明文、完整 opcode 表。载荷解到 14,937 个 u32 字（59,748 B）后
仍是白化态（熵 7.9958 bit/B；`≥2^32` 组占比 3.21% vs 理论 3.20% ⇒ 框架正确、内容确为均匀随机）。
最后一层需要按序复刻 loader 状态机（≈270 状态 × 4 树），超出一次性纯静态预算；
一个运行期 hook（`buffer.fromstring` 入参或 `decode` 出口）即可完全打开。
